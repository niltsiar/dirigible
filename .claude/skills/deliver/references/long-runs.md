# Long autonomous runs

- Before a loop, write its stop predicate in the first `run.md` (for example, `scripts/wiki.py list next` has no product item); never relax it to stop.
- Take the next goal from `scripts/wiki.py list next --ready`, else the next open item of `docs/requirements/releases.md`, and close each run before the next. The cadence of the steering runs is in `docs/workflow/release-cycle.md`.
- Read `AGENTS.md` from disk at the start of each run.
- At most two runs are in code; beside them, keep 2 or 3 lock-free agents at work (plan, plan gate, review, research); run `scripts/with-lock.sh --builders` to list the building trees. A third tree waits in `scripts/with-lock.sh`. A push check, a land, or a mutant runs alone: beside it, run only the code gate reviewers, plan writing, plan gates, other reviews, and doc-only edits in another worktree (no build, no test, no lock-held make), and light read-only work: the Phase 0-2 reading of the next goal, research, run files, built files, and evals except `agent`-type rows. Commit a doc-only edit after it ends, because the commit hook runs `make lint`. Start an `agent` eval row after it ends. A heavy read-only command (a history scan, a transcript replay, a loop over many files or processes) runs as `WITH_LOCK_NO_CAP=1 scripts/with-lock.sh <command>`: it waits for the build or test of any tree and takes no slot of the cap. Start no build or test in any worktree, and no on-screen check: timing tests fail under load. While a bench or a flake loop runs, start no build, test, commit, or on-screen check; the lock-free agents keep working.
- Before the first run of an unattended loop, check the access of Phase 9: `git ls-remote origin`, `gh auth status`, an allow rule for `scripts/land.sh` in `.claude/settings.json` (add it if missing), and a permission mode that allows file edits. If one fails, stack each run branch on the previous one, record it in `run.md`, and land them when the human is back.
- Use only the access that these two commands already have; leave credential stores closed.
- Each run lands green on `main` through its own pull request.
- At a pause, leave each open run at a slice commit or with its working tree as is, and write in `run.md` the next step and each check result, taken from its command output or log, not from memory; make no `wip` commit.
- With `schedule_task` (T3 Code only), end the turn behind a scheduled wake when a wait is over 4 h and nothing runs: a Monitor holds the session for 4 h at most. Call `schedule_task` with a `fixed_time` schedule bound to the thread; for a wait over 24 h, set `weekdays` to the day of the wake; for a wait over 6 days, set the wake again at the first wake. The task ID exists only after the call returns, so then call `update_scheduled_task` to set the prompt to "First call delete_scheduled_task <id>, then continue with <the next step of run.md>", and write the ID in the `run.md` handoff. The wake turn deletes the task first, because a `fixed_time` schedule runs each day. A wait of 4 h or less keeps the re-armed Monitor of `AGENTS.md`.
