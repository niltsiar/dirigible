## Decision

**Mix.** `MixReader` in `DirigibleAudio/Render/` renders the session mix: stereo float32 at the session rate, clip gain plus track gain in dB as one linear factor times the fade factor of 0035 of the sounding clip (0036), a mono track in both channels at unity (0007), and silence where there is no clip or no media. Each read is clamped to `AVAudioFile.length`. It keeps at most 32 files open and closes the least recently used one. A file that does not open because the process has no free descriptor (EMFILE, ENFILE) is not a media fault: `dirigible render` fails with exit 2 and leaves no output, the media check keeps the last state, and a play stops with its own cause, `PlaybackStop.noFreeDescriptor` (code gate 1 item 2 and its sibling). Playback, `dirigible render`, and the export of run 5 use this one render, so they cannot differ.

**Player.** `actor Player` in `DirigibleAudio/Render/` owns one `AVAudioEngine` with one `AVAudioPlayerNode` into the main mixer, on the system default output. It never sets the output device (E9). It starts the engine at each play and stops it at each stop, off the main actor (E10). A play schedules 0.1 s chunks, 3 ahead, and refills from its own tick. When a refill finds that the node ran dry and its time went on (an underrun, for example a slow disk), it starts the node again at the last frame that the node played. The Player position is the node position less the output presentation latency. So the playhead is the frame that the user hears (code gate 1 item 1). `Studio` makes the Player at the first transport command. A play awaits the session update before it starts, so it plays the latest session. Only play, stop, seek, and shuttle take a new feed number; the actor ignores a command with an old number. An edit, undo, or redo sends the session on its own path with a revision and no feed number, so the feed goes on and a play that waits is not dropped. Reverse play renders a chunk forward and flips it. A rate other than 1x (0.5x, 2x, 4x) resamples the chunk by linear interpolation, with tape pitch; `AVAudioUnitVarispeed` is not in the path (E3). Tests run the same graph in offline manual rendering. This amends 0002: the Player is an actor, not `@MainActor`. Amended 2026-10-03: the actor runs on its own `DispatchSerialQueue` (QoS user-interactive), as each capture writer does (0004). A play starts a `DispatchSourceTimer` on that queue; each tick (half a chunk, 50 ms) runs the refill, and the next command cancels it. On macOS 15 and later the tick calls `assumeIsolated`: a plain dispatch block, with no thread of the cooperative pool. The reason is measured, not assumed: AVFAudio delivers `.dataConsumed` on `AVAudioPlayerNodeImpl.CompletionHandlerQueue` at QoS 21, and with the pool held at QoS 21 or more it ran only when the hold ended; the timer ticked on time with 32 blocking pool jobs at 17, 21, 25, or 33 (`TaskPriority(rawValue: 33)` exists), at most 10 ms late, as with no holders (probe E8, `.scratchpads/runs/2026-10-03-player-executor/probe/p2-timer/output.txt`). The gate is the availability of `SerialExecutor.checkIsolated()` (macOS 15.0; `DispatchSerialQueue` checks with `dispatchPrecondition`, SE-0424). On macOS 14 the tick keeps a `Task` hop: in the legacy runtime mode, `assumeIsolated` from a dispatch block crashes (E2). No macOS 14 machine checked it.

**Studio.** `Studio` stays the facade. It adds `playback` (stopped or playing with a direction and a rate), `playhead`, `missingMedia`, `playbackStop`, `perform(TransportCommand)`, and `checkMedia()`. `Studio.transport` does not change. A transport command during a take start, a take, or a finalize does nothing, except Space, which stops a take. Record stops playback and starts the take at the playhead. Every take path accepts Record with no await first: it sets the take-start state and a new feed number before it stops the Player, so no play can start into the take. The Player stop is the first step of the serialized take start, so `settle()` waits for it. The take starts at the Player position only when the Player started the play that Record stopped; else it starts at the playhead. At open, the playhead is the session end, so Record in a reopened session appends. The package does not save the playhead. The record-over chip over the track headers shows when the first clip that Record reaches on an armed track is not in view (see 0017). After a finalize that succeeds, the playhead goes to the largest end of the clips of the new files of the take. A punch-in split gives an old file a new clip ID, so a new clip ID does not mark a take clip (code gate 1 item 3). `settle()` stops playback first. Edits, undo, and redo work during play; the next chunks use the new session.

**JKL.** J plays backward. A tap latches: L plays forward; each more L while forward goes up a rate (1x, 2x, 4x); Shift-L plays at 0.5x; J mirrors L; K pauses. A hold of 0.3 s or more plays while held, and the key-up pauses, as Hindenburg does (research: "hold them down to play"; build 2572 ignores auto-repeat). One local key monitor drops the auto-repeat of J, L, and Space (H1) and reads the key-up of J and L; a held Space so acts once (code gate 1 item 8). It matches the keys by character, as the menu items do, not by key code (code gate 1 item 5); the menu items keep the keys. The key-up decision reads only the stored key-down, and the release pauses the Studio of the key-down directly, with no key forward, also when the key focus moved during the hold (code gate 1 item 7). The media check runs only when a play starts from stopped, not at each shuttle key. Paused and stopped are one state: the playhead stays where play stopped. "Hold K for fast" (K+J, K+L) is not in Release 1.

**Missing media.** `checkMedia` runs off the main actor at open, after each finalize, at each play start, and at window focus. It stats each pool file first (a missing file has no own open error, E6a), then opens it and compares the rate, the channel count, and the length. The states are `.missing`, `.short(frames)`, and `.unreadable`. A read error during play marks the file `.unreadable`. A package that left its volume is not a media fault: the check keeps the last state, and the play stops with its own cause, `PlaybackStop.packageUnavailable`, at the play start and at each refill. Each refill reads the package path that the lock holds now, so a rename during a play reads the renamed package (code gate 1 item 4). The window shows the paths in a banner. Run 4b draws the clips.

**Keys.** A Transport menu has: Play or Stop (Space), Stop and Return (Shift-Space), J, K, L, Shift-J, Shift-L, Go to Start (Home), Go to End (End), Previous and Next Clip (Shift-Left, Shift-Right). A menu item with a plain key takes the key also when it is disabled (K1), so these items are never disabled. Each action first reads the key window. When it is not a session window (a panel, an alert), or its first responder is text, the action gives the key event to that first responder (K3) and does nothing else. Record stays Command-R: Hindenburg PRO 2 uses Command-Space (Spotlight) or Control-Space (input source).

**CLI (0011).** `dirigible render <package> --out <file> [--from N] [--to N]` writes the mix as a 32-bit float stereo CAF at the session rate. It renders in chunks into one reused buffer, so the memory does not grow with the range. It writes a temporary file next to `--out`, then moves it with `renamex_np(RENAME_EXCL)`, which never replaces an item. Where that call gives ENOTSUP or EPERM (exFAT, X1), it claims `--out` with `O_CREAT | O_EXCL`, then renames over the claim. So it refuses an output path that exists (exit 2), and a render that fails leaves no `--out`. Every exit removes the temporary file, and Control-C (SIGINT) does too. At its start, a render removes the `.<name>.<UUID>.tmp` files that a render to the same output left when it died (code gate 1 item 6). A missing file gives one warning line on stderr and exit 0. `dirigible info` shows the media state of each file (JSON key `media`).

## Consequences

- 0002 gets an amended line: the Player is an actor in `Render/`.
- 0003 gets an amended line: the missing-media check points and states.
- 0011 gets an amended line: `dirigible render` and the `media` key of `info --json`.
- 0014 gets an amended line: the Transport menu keys, and a take starts at the playhead.
- Each play has 30 to 50 ms of latency for the engine start. Nothing holds the output device while stopped.
- An edit during play is heard within 0.3 s. A rate or direction change restarts the feed with a short gap.
- A plain-key menu item looks enabled while a take records. It does nothing then.
- A headphone unplug is a manual check: the probe did not reproduce the notification.
- A user who holds J or L for 0.3 s or more gets a pause at the release. The threshold is a calibration knob.
- A reopened session loses the playhead of the last visit.
- Two renders to the same output at the same time: the second removes the temporary file of the first, and the first fails its move. Neither leaves a bad output.
- An underrun gives a gap of silence, and the play goes on at the frame after the last heard frame. The latency subtraction has no automated test: offline rendering has no output latency. A manual check covers it.
- Run 5 builds `exportMix` on `MixReader`, and adds the mono fold and the missing-media confirm.
- On macOS 15 and later a full cooperative pool does not delay the refill. `PlayerTests.aHeldPoolDoesNotDelayTheRefill` (slow) holds the pool at 17, 21, 25, and 33 during a paced offline render. On macOS 14 a refill can still be late, and an underrun gives a gap as before.
- A play ticks 20 times per second until the next command. `PlayerTests.aStopEndsTheTicks` checks that no tick runs after a stop.
- A call of `Studio` into the Player was not measured under a held pool. The playhead poll sleeps 33 ms with `Task.sleep`, which needs the pool, so a full pool can delay a playhead update.

## Alternatives considered

- **One player node per track or per clip with `scheduleSegment(at:)`** (E4). Rejected: no clip gain (E1b), no reverse, and a second mix path for export.
- **An `AVAudioSourceNode` with our own ring.** Rejected: our own real-time code, while `scheduleBuffer` is sample-exact (E1).
- **A public Player next to Studio.** Rejected: the app would coordinate two transports.
- **`@MainActor Player`.** Rejected: HAL and file work on the main actor (E10).
- **J as skip-back.** Rejected: reverse is one flip of a rendered chunk.
- **Latched JKL only.** Rejected: Hindenburg JKL plays while held (research), and H1 shows that a key-up monitor works with the menu items.
- **Hold-only JKL.** Rejected: the repeated-L ladder needs a press that stays.
- **Save the playhead in the package.** Rejected: a change of the 0003 format for a value that End sets again.
- **Plain keys in a local event monitor, not in the menu.** Rejected: the release rule asks for a menu item with its key.
- **`AVAudioUnitVarispeed` for the rates.** Rejected: it changes the signal at 1x (E3).
- **The `.dataConsumed` handler as the refill trigger, run on the Player queue.** Rejected: AVFAudio delivers it on a QoS 21 queue that a full pool delays (run 2026-10-03-player-executor, slice 1).
- **The feed state in a class confined to the queue (`@unchecked Sendable`).** Rejected for now: it also fixes macOS 14, but it is larger and loses the compiler isolation checks. Take it if a macOS 14 user hears a gap.
- **A higher priority for the refill task.** Rejected: the pool is shared across priorities.
