## Context

R8 asks for noise reduction; F35 asks for one control, F77 for hum removal at 50 or 60 Hz, and `releases.md` run 20 for a render into a new file as one undo entry. 0009 chose AUSoundIsolation and said that the session stores the effect and renders it at each play. The research of this run (`docs/research/render-denoise.md`, probes on macOS 15.7.9, Intel) found: the unit isolates voice, so it also removes hum and music; its wet/dry mix is linear (a reduction of -20 log10(1 - wet) dB); its latency depends on the channel count (56.35 ms mono, 76.35 ms stereo at 48 kHz); the dry path at wet 0 is exact after the latency trim; with 2 channels it applies one mask and moves no audio between channels; it renders at about 8x real time. Hindenburg PRO has one noise reduction dial; Logic Selection-Based Processing, Audition Waveform effects, and Audacity render to new audio.

## Decision

- **One render path.** `renderClips(groups, ...)` in `DirigibleAudio/Render/` is the path of each clip effect (this run; runs 23, leveler, and voice-match reuse it). Each group is a list of clips and one `Treatment`; one call renders all groups and commits their files in one batch, and the caller writes `session.xml` once. An effect that measures (a ride, a voice match) measures all groups before the first write. It takes the clips of one run of one file (the clip spans plus a 10 s handle on each side, or half the edge crossfade when longer, capped at the file; runs whose spans touch merge, as split stereo) and writes one new 24-bit WAV for each run. Each clip keeps its ID, start, length, gain, fades, and crossfades, and points at the new file at (old offset - run start) (`Session.repoint`, the one Session call of the clip edit). Its envelope keeps the gain at each source frame: each point moves by -(run start), with the edge rule of 0060 at the edges of the new file (`GainEnvelope.moved(by:fileLength:)`, which the split also calls). `repoint` adds the new file through `Session.addDerivedFile`, which sets the length, the layout, and the `capture`, and copies the transcript words of the source span; split stereo uses the same call. The source WAV stays in the pool. A rendered file has no take origin (0061).
- **Engine.** A new AVAudioEngine in offline manual rendering for each run, at the file rate and channel count: a player node fed with blocks that `AVAudioFile.read(into:)` reads (a read fault stops the render; no `scheduleSegment`, which gives silence on a fault), then the hum band-stop (`AVAudioUnitEQ`, bands at f, 2f, 3f, 4f) when asked, then AUSoundIsolation (Voice model, on every macOS) when asked. Stereo is joint: one unit for both channels. The render runs off the main actor.
- **Latency.** The render reads the latency of each unit after the format is set, renders the span plus that many frames, and drops the first round(latency x rate) frames. No code uses a latency constant.
- **Amount.** `NoiseReduction` (in `DirigibleAudio`, not Core: an engine setting) is whole dB from 1 to 30, default 12 dB (wet 74.88 %). `Treatment` is a set of effects (`noise`, `hum`; later runs add more), each kind once, in the fixed chain order, with no empty set and no combination case. The app, `dirigible clip denoise`, and `clip_denoise` parse into these types. The app keeps the last sheet values as preferences under new keys (0024 P11); the CLI and the tool do not read them.
- **No format change.** The session stores no effect and no provenance. `session.xml` keeps its version. A change of amount is Undo, then a new render. A second render of a rendered clip processes processed audio.
- **Files and commit.** The order is the order of the split pair writer, so a refusal reads no audio and writes no file: the run and session checks, the role check (a clip on a music or effects track refuses when the treatment holds noise), the source checks (a source that is missing or whose data is not on this Mac refuses), the unit load for each channel count of the runs, one space check in `NewClipFiles` (the bytes of all new files plus 1 GB), the stems, and `repoint` on a session copy. Then each run renders into `.<stem>.wav.tmp`, with at most two source blocks of 65,536 frames in the player node, so a run of any length holds about 1 MiB of source buffers in stereo, and with the flush and the read-back and a check that the length equals the run span; the renames come after all runs; the stem is `<stem> NR` (noise) or `<stem> HR` (hum only), the suffix of the `Treatment`, by the one stem rule of `NewClipFiles`, unique among the files of one render (`<stem> NR 2`). A run with a peak over full scale renders again with a scale (a constant in the one gain stage after the unit, so the second pass peaks at full scale or under, as the A11 pass of import; a second pass that still peaks at the largest 24-bit sample throws `stillOverFullScale(file:)`, and no file stays), and after the writes its clips get the same dB of clip gain through `Session.setGains`, clamped to the gain range as a paste across rates. The commit point is the `session.xml` save. A throw before the renames leaves no new file; a fault in the renames or the flush of `Clips/` keeps the renamed WAVs as unused files and changes no session (0040); a cancel after the renames removes them with `removeMadeFiles`; the work of `blockingRun` returns the made files, and `blockingTurn`, and the files body of `ClipRenderWork` for the CLI and the tool, remove them at a cancel or a take yield before the save (the helper of 0049 part 2). A failed save keeps the renamed WAVs (0040). One undo entry.
- **Studio.** `Studio.renderClips(_:treatment:agent:progress:)`, the one Studio call of each render effect, is a blocking run of kind `.clipRender` (0040): `.busy` during a take, an import, a paste or split run, or `settle()`; the banner with Cancel; a take start in another window yields it; one undo entry that names the agent of an MCP call. `blockingRun` holds `ProcessInfo.beginActivity([.userInitiated, .idleSystemSleepDisabled])` in each blocking run (import, paste, split, clip render) from the end of its refusals (`.busy` and the ripple check) to its end, a cancel or a throw included, so idle sleep and App Nap do not stop a long render. Progress is the frames done over the frames of all runs, reported when it rises by 0.1 % or more (so about 1,000 main-actor updates for a render of any length), and 1 only at the end of the last run; a second pass holds the fraction until its run ends (0049). It returns `ClipRenderReport` (each moved clip with its new file, in run order, and the `NoiseReduction` of the treatment, nil when it has no noise effect). `renderClips` is `package`, because `ClipRenderWork` in `DirigibleMCP` calls it; `ClipRenderError` is public. Its test seams are parameters (`component:`, `readFault:`) and the `CaptureEnvironment` fields `clipRenderRead` and `clipRenderWorkDone`. The reason text of the activity is the field `blockingRunReason` (live value: the fixed text). One `ClipRenderWork.lines` formats the moved clips for the CLI, the tool on the files, and the tool in the app.
- **Errors and load failure.** The render errors are one type, `ClipRenderError`: `space`, `write`, `sourceUnreadable`, `sourceMissing`, `notDownloaded`, `cancelled`, `session(SessionError)`, `trackRole(clip:role:)` (a clip on a music or effects track; before any read), `mixedTreatments(clips:)` (the clips of one run come from groups with different treatments; the runs come from the clips of all groups at once, as `repoint` finds them; before any read), `effectUnavailable(status:)` (the unit does not load; before any write), `engine(status:)`, and `stillOverFullScale(file:)`. Each text names the noise reduction, never an import. The names take the prefix `ClipRender`, because "render" already names the mix render of `dirigible render`. No fallback in this run.
- **Interface.** Tools > Reduce Noise (no key), on the clips of the 0031 rule that are on a track with no role or the dialogue role, off when the selection has no such clip; a result banner. The unit isolates voice, so it would remove the music of a music bed and the sound of an effect: `Treatment.accepts(_:)` is the one rule of the app filter and of the refusal of the CLI and the tool. Hum removal alone (landing 2) takes every role. The sheet (dial, Preview with Result and Removed Sound, Remove Hum) is landing 2. Preview renders a 10 s window into memory with a new chain, off the main actor, from the playhead when it is inside the clip, else from the clip start, and moved back from the clip end so that it holds 10 s or the whole clip; Removed Sound is the aligned input minus the result; the latest dial value wins.

## Consequences

- The old WAV stays until Remove Unused Files (0047); Undo and the backups hold it. A render costs disk space: a 1 h mono clip writes about 518 MB at 48 kHz.
- Each reader (play, export, loudness, peaks, Auto Level) hears the new WAV with no change.
- A reduced clip trims out only to the edges of its new file: at least the 10 s handle, more inside a run. A longer trim needs Undo of the render.
- After Remove Unused Files moves the source WAV, the take stays placed, because the new file keeps the `capture`.
- A re-render after a relaunch needs Undo (gone after a relaunch) or Revert to a backup (0043).
- macOS 14 and Apple silicon are not tested; a load failure shows its cause, and the spectral fallback of 0009 becomes due.
- A noise-only channel next to a voice channel stays about 1 dB more open at 12 dB (the joint mask).
- On 60 s of real speech of a published tester podcast, 12 dB changed the integrated loudness by -0.56 LU and lowered the noise floor of the pauses by 11.09 dB (the raw unit on macOS 15.8, x86_64; worked fixture of the run). A listen check at 6, 12, and 24 dB comes with the dial (landing 2).
- A clip on a music or effects track keeps its audio; to reduce noise in it, give its track no role or the dialogue role.

## Alternatives considered

- **Provenance in `session.xml` (version 8).** A re-render from the source with no stacking and an inspector row, but a new holder rule (0047), reader refusals, and older builds that refuse the package. Rejected.
- **A live effect at each play (0009 as written).** 56 to 76 ms of latency and 1/8 of real time for each clip at each play and export. Rejected.
- **The raw AudioUnit pull with an input proc.** Exact, and the probes used it, but an input proc and its context memory under 0013. Kept as the fallback if the engine graph does not null.
- **One file for each clip.** A seamless cut becomes a butt join, and dense edits repeat the handles. Rejected.
- **`vDSP.Biquad` notches for hum.** Own DSP; kept as the fallback if the band-stop of `AVAudioUnitEQ` is too wide or too shallow.
