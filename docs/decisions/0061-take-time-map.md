## Context

A tester edits a recorded episode through an agent (walkthrough of 2026-10-16, report section 2). Each ripple insert or delete moves the audio, and the times of a transcript, of the chapters, and of a video that were made on the recording stop matching. The agent kept a log of each insert and shifted the SRT with a script. The tester asked for an original-to-edited time map, an SRT import and an export of the edited timeline (F118, F121), and a warning when an edit breaks the sync with the take.

What the session has: each finalized capture file is placed at the aligned start of 0004 (playhead + host time offset - latency). The take anchor file `Capture/take<n>.anchor` keeps the `Recording` of each ended take, and no tool deletes it (0021). The capture record keeps the host time, the latency, and the nominal rate of finalize. So the take time of each frame of a capture file can be computed again from data on disk. Transcripts store words as file-frame anchors (0055), so the words follow each clip edit already. Markers follow each ripple (0037 Rule M).

Probe p1 of the run replayed the aligned start formula on the session of the tester: it predicts the 294-frame origin difference of the two devices of take 4, and the session (head trimmed by 29.496 s on both tracks) is one constant shift of -1415798 frames from the take. Probe p2: a millisecond time goes to frames and back with no change at 8 kHz to 192 kHz.

## Decision

**Take time.** The take time of a frame of a capture file is its time from the record start of its own take: the aligned start of file frame 0, minus the playhead at record start (`Recording.playheadFrame`), plus the file frame. Each take has its own take time, so take time 0 of take n is the record start of take n, and a transcript of one take file needs no `at`. `Capture.alignedStart(in:sampleRate:)` in DirigibleCore is the one formula; finalize (`SegmentFinalize`) and the map both call it.

**Origin.** A file has a take origin only when its `capture` ID equals its file ID (the file that finalize made) and the anchor of its take reads. A read fault (an errno other than ENOENT) is not "no origin". A fault of `Capture/` keeps every take out of the map, and `TakeAnchors.read` throws it. A fault of one anchor keeps only its own take out: `TakeAnchors.read` gives it as the entry of that take, and the other takes keep their map and state. `take map` and `take_map` fail on the fault of the take that they map, or with no `--take`, on a fault of a take with a capture in the session. `info` shows one fault line for each fault after the sync lines, `info --json` and `session_info` show one `takeSyncFaults` entry for each fault, and both still answer; only the edit note leaves out the line of a faulted take. In the window, a fault never stops or rolls back an open, a take end, or a placement: it goes into the `takeAnchors` value of the open and of the take outcome, not into their error, and `Studio.takeSyncFault` names it, because the take end writes `session.xml` before the outcome reaches the studio. The anchor files keep the take time, so they must stay in the package. A file made by an import, a paste across packages, or `addDerivedFile` has no origin, and the map ignores it. A take that ended before 0021 has no anchor, so its files have no origin. A segment placed with `capture place --at` keeps its recorded origin: it is out of sync when it is not at its recorded time.

**Map.** `TakeMap(session, recordings:)` is a value made from a session and the `Recording` of each capture. For a take n, a take frame t, and each track, each clip of a file of take n whose origin is o and whose take range `o + offset ..< o + offset + length` holds t gives the timeline frame `start + t - o - offset`. No such clip gives `cut`. Two clips give two frames (a pasted copy). The inverse gives, for a timeline frame on a track, the take frame of the clip under it, or `none` (a gap, an imported clip, or a file with no origin). The map uses the file range of each clip, not the crossfade handles.

**Sync state.** The shift of a clip with take audio is `start - o - offset`: the timeline frame of take time 0. The reference shift of a take is the shift whose clips hold the most frames (the sum of their lengths); a tie goes to the shift of the earliest clip. A clip at another shift is a copy when the clips at the reference shift on the same track play each frame of its take range: a cold open, a short copy of take audio pasted at the start, is a common podcast edit, and it must not hide a later break. A copy on another track than the audio that it copies is not a copy. Each take with audio has its own `TakeSync`, from the clips that are not copies: `inSync(offset:)` when every such clip of its files on every track has one shift (0 frames of tolerance), or `broken(from:shifts:)`: `from` is the smallest start of such a clip whose shift differs from the shift of the first such clip in timeline order (track order breaks a tie), and `shifts` is the count of their different shifts. So `from` stays at the edit that broke the sync, also when the moved part is longer than the part before it. The session state is the list of take states; an empty list is no take audio. A take that no edit changed is in sync at the playhead of its record start, so a take recorded after an edit does not break the takes before it.

**Edit note.** `TakeSync.change(from:to:)` is the one function that decides a transition. Each MCP tool call that changes the session gives one more line for each take whose state changes class, or whose `inSync` offset changes: `Take sync: take <n> <before> -> <after>`. From `broken` to `broken` there is no line, so a normal cut-by-cut edit gets one line, at the first break. A take completion or a placement is never a transition, and a take that is in only one of the two lists gives no entry, both ways. In the window, `Studio` makes the state and its change once per revision, in `poolChanged(from:agent:)`, and stamps them with the revision and its agent: the `agent` of `edit`, `redoAgent` for a redo, the `agent` of an audio import, and nil for an undo, a take outcome, and a prune. A no-op edit does not move the revision and gives no change. Each revision uses the anchors of its own session: the open and each take outcome carry the anchors, and the studio caches them before `poolChanged`; there is no async refresh. `LiveCall` and `LiveJob` read the change when its stamp is newer than the revision before the call. The closed path wraps the MCP calls that can move clips (edit, paste, import, revert). For a closed package, one MCP helper wraps the edit body that it passes to `editPackageCore` and reads the anchors under the same lock; `editPackageCore` does not change, so the CLI edit path does no take-sync work. The CLI prints no note: `dirigible info` shows the state.

**Surface (0011, 0041).** `dirigible take map <package> <frame>... [--take <n>] [--timeline] [--track <id>]... [--json]` (take frames to timeline frames, or the inverse with `--timeline`; one line for each frame) and the read tool `take_map` (`frames`, `take`, `timeline`, `track`). `--take` may be left out only when the session has one take with audio; else exit 64 with the list of takes. `info` (one line per take), `info --json` (key `takeSync`, a list), and `session_info` (also with `compact`) show the state. A session with no take audio: `take map` exits 1 with "The session has no take audio with a take time."

**SRT import (F118 part).** `TranscriptFile` reads SRT: content that is not WebVTT and does not start with `{` or `[` after white space, with cues of an index line, a `HH:MM:SS,mmm --> HH:MM:SS,mmm` line, and text lines. One unit per cue, as WebVTT. The reader takes an optional index line, any hour width, a comma or a dot before a decimal fraction, CR, LF, or CRLF, and a UTF-8 BOM, and skips a cue with no text (`docs/research/take-sync.md` findings 36 to 45; ffmpeg reads the fraction as whole milliseconds, Whisper always writes three digits).

**App (0014, 0023).** One banner row when a revision with an agent (an agent edit or import in the window, or the user's Redo of an agent entry; never an Undo) moves a take from `inSync` to `broken`, with Undo and Show (the playhead to the break); a user edit shows no row, because a podcast with no video gets a ripple edit at almost every cut. The banner reads the studio change by its revision stamp. The Episode inspector always shows the state, one line per take; Transport > Go to Take Time... (Command-J) moves the playhead to the first timeline place of a take time; File > Export Transcript... writes the file of `transcript export`. `Studio.takeMap` and `Studio.takeSyncChange` are made once per revision. No clip badge, no session setting, no toolbar item.

**Take-time import.** `transcript import --take <n>` and `transcript_import` with `take` (a take number) read the unit times as take time of take n: frame = round(seconds x rate) + `at`, and the clip of a file of take n on the import track whose take range holds the midpoint gives the file frames. A unit in audio that an edit removed is skipped and counted. The result names the take and the placed and skipped counts, so a wrong take shows as a high skip count. So a transcript of the recording imports onto an edited session. Without `--take`, the import is as in 0055.

**Export (F121 part).** `dirigible transcript export <package> --out <file.srt or file.vtt> [--transcript <id>] [--replace]` and `transcript_export` (`out`, `transcript`, `replace`) write one cue for each shown unit of the transcript, in timeline order, with the times of `Session.words` (clamped to the clip) in milliseconds, `round(frames x 1000 / rate)`. Units of one word at one start on two tracks give one cue. A unit with an empty range is left out and counted. More than one transcript with no `--transcript` is refused and lists the IDs. As chapters export, an existing file is refused unless `replace`, a path inside a session package is refused (`ExportText.checkOutsidePackages`), and the write is atomic, so an export never replaces a file that the user did not name with replace.

## Consequences

- No `session.xml` change and no new file format: a session keeps its version, and an older build opens it.
- The map of an open window costs no file read per edit: Studio keeps the anchors of the package (read off the main actor by the open and by each take end or placement, and carried in their result to the main actor), and makes the map from the session of each revision once.
- A derived file of a later run (split stereo, render) has no origin until that run stores one: that run needs a `session.xml` change for it.
- A transcript of one take file, or of a call recording that started with the take, needs no `at`. A take file whose first frame is before the record start (a pre-roll take, 0004 **Timing**) has file frame 0 at a negative take frame, so a take-time import of a transcript of that file needs that negative `at`. A transcript of a timeline that was already edited before the transcript (the tester's head trim) needs `at`: the take frame of second 0, which `take map --timeline 0` gives before the edit.
- A cue that an edit splits is clamped to the clip under its midpoint (0055), so the export can shorten it; the text is not split.

## Alternatives considered

- **A stored origin, `origin` on `<file>` (version 12).** It also covers derived files, but it is a one-way format change, it needs the same anchor read to fill old sessions, and no derived-file edit is on main. Rejected for now; the first derived-file run takes it.
- **A log of the time edits in the session (the tester's first idea).** It sees only the ripple edits: a move, a nudge, an overwrite paste, or an import onto a take track changes the sync with no log entry. The clip placement is the truth that the audio plays.
- **A reference snapshot that the user sets ("Set Sync Reference").** It covers a transcript made after an edit that already broke the sync. It needs a stored value (a format change) and a new command; `at` covers the constant-shift case that the replay showed. Later.
- **A transcript-relative reference** (the timeline at the import). It needs the import-time clip layout, which the store does not keep.
