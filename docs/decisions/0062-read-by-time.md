# 0062. Read the audio by time: one window scan, silences, the nearest pause, and the range meter

- Status: accepted
- Date: 2026-10-23
- Accepted: 2026-10-23, after plan gate 1 of run `2026-10-23-read-by-time`.
- Amends: 0060 (the speech runs of the duck come from the shared window series on the frame 0 grid, cut to the scope), 0039 (`silences` and `nearest_pause` ignore mute and solo; `meter` follows the flags, as the Mix bullet says), 0011 and 0041 (three read commands and tools), 0049 (three more long tools), 0051 (the core rule on reads by time).
- Amended: 2026-11-01, run `2026-10-28-silence-tool` (see 0066). The Silences tab builds its rows on `LevelSeries.silences`. `checkedMixLevels` holds the media check, the mix, and the fault read, and both `ReadWork.levels` and the scan call it, so a fault refuses both reads with the same files.

## Context

An agent edits an episode over MCP. To place a cut, a marker, or a duck, it must know where the pauses are and how loud a range is. Today the manual says "No tool reads the audio by time", so the tester agent exported the mix and measured it with ffmpeg and Python (`silencedetect`, a 10 ms RMS envelope, `ebur128`). F96 (Release 5) needs the same pause detector for its review list.

Grounding (run analysis, probes P1 to P3):

- `speechRuns` (`DSP/SpeechActivity.swift`) already scans a mix: `MixReader` on a copy of the session with mute and solo off, 1 s chunks, 50 ms windows, the mean of the L and R mean squares against `10^(dB/10)`, progress and cancel. It is the only window detector.
- `LoudnessMeter` gives the 400 ms blocks (the momentary series at a 100 ms hop) and the BS.1770 gated value. It keeps only the last 30 steps, so it has no short-term series. `TruePeakMeter` gives the largest true peak. The record path feeds `LoudnessMeter` on the writer queue, not on the real-time thread (`TrackSegments.swift`).
- An agent read on an open session reads the window session, not the files: `Studio.measureLoudness` copies `session` and runs on a utility GCD thread in `lock.package()`.
- On 66.5 min (probe P2, debug build): the mix render is 4.82 s; the meter work is the limiter (216 s debug for 2 x 66.5 min; 1.88 s per hour optimized for K-weighting).

Rubric: (1) one definition of "quiet window" for the duck, the reads, and F96; (2) the rules testable with no audio file; (3) one audio pass per call; (4) no change to the record and live meters; (5) the smallest public surface in `DirigibleAudio`.

## Candidates

**A. One scan with visitors.** A `scanMix` loop in `DirigibleAudio` gives each chunk to visitor objects: a run detector, a quietest-window finder, and a meter. Each read is a visitor. Score: (1) yes, (2) no: each rule needs rendered audio in its test, (3) yes, (4) yes, (5) medium (a visitor protocol with three conformers).

**B. A window level series, then pure rules.** One audio function gives the series of each 50 ms window of the range: its mean square and its sample peak. The rules are pure functions on the series in `DirigibleCore`: runs over a threshold (the duck), silences (the complement with a minimum length), the nearest pause, the quietest window, and the step values. The meter is a second sink of the same scan. Score: (1) yes, (2) yes: arrays in, ranges out, (3) yes, (4) yes, (5) small (two functions).

## Decision

Synthesis: B, with the single chunk loop of A as the one private scan.

- **Scan.** `DirigibleAudio/DSP/MixLevels.swift` holds one private chunk loop (from `speechRuns`) and two public functions: `mixLevels(of:in:package:range:silence:...)` gives a `LevelSeries` and the unread files; `measureMix(...)` gives a `MixMeasure` and the `LevelSeries` from the same pass. `mixLevels` (the duck, `silences`, `nearest_pause`) reads `Session.ignoringMuteAndSolo`, the one owner of the copy with mute and solo off, as the duck and Auto Level (0039): a pause search must not change when the user mutes a voice to listen. `measureMix` (`meter`) reads the heard mix, `Session.heardTracks(in:)`, as the export and the loudness meter (0039 Mix bullet). Track list nil: every track. `speechRuns` becomes `mixLevels` + `series.runs(over:)` cut to the scope + `shape.merged`.
- **Grid.** Each window starts at a multiple of the window length from session frame 0. The first window of a read starts at `floor(from / window) * window`, and the scan ends on a grid frame or at the session end. So one frame has one window, and two reads with different `from` values give the same windows. A duck of the whole session (scope `0..<end`, `Session.duckScope(nil)`) reads the same windows as before, because `speechRuns` starts its grid at the scope start. A ranged duck can read up to one window before its scope start and past its scope end; its runs are cut to the scope, so they stay inside it (0060 amendment).
- **Series.** `DirigibleCore/LevelSeries.swift`: `range` (a `Range<Frames>` that starts on the grid), `window` (frames, `max(1, rate / 20)`), and `levels` (one `WindowLevel` for each window: its mean square and its sample peak). The window count and the length of a short last window come from `range`. `init?(range:window:levels:)` returns nil when `levels.count` is not the window count of `range`. Pure methods: `runs(over:)`, `silences(threshold:minLength:in:)`, `nearestPause(at:window:threshold:minLength:)` (with no silence, it gives the quietest window), `steps(of:)`.
- **Silence rule.** A window is silent when its mean square is at or under `10^(threshold/10)`: the exact complement of the speech rule. A silence is a run of silent windows. The order is: (1) the scan finds each run of silent windows with its uncut extent; (2) the minimum length applies to the uncut run; (3) the read reports each run of `minLength` frames or more that intersects the asked range, with its whole extent. For the uncut extent, the scan reads past each edge of the asked range until the run that crosses the edge ends (a window over the threshold) or the session edge. When no run crosses an edge, one window past it is enough. This covers the margin of `minLength` that the minimum needs. The extra read is the length of that one silence, and at most 1200 windows (60 s) past each edge (`LevelSeries.edgeWindows`). A silence that goes on past that limit is reported up to it, with the warning line of Texts. 60 s holds each pause of speech and a long gap of room tone, and it bounds a `nearest_pause` of 4 s to at most 124 s of audio, so a quiet track or a high threshold cannot turn a short read into a read of the whole session. The progress is the fraction of the most frames that the read can read, so it also counts the frames past the edges. A silence that reaches the session start or end stops there: its line shows frame 0 or the session end frame, with no other mark. So a silence across a page edge of `silences` has the same line on both pages (unless it goes on past the limit), and the report of a run does not depend on where the asked range starts. Edges are on the frame 0 grid: probe P3 puts a 50 ms edge at most 40 ms inside the 10 ms edge.
- **Pause rule.** The asked range is `at - window ..< at + window`, cut to the session. The scan reads past its edges as for `silences`. The pause is the silence (the minimum applied to the uncut run) that intersects the asked range and is nearest to `at` (distance 0 when `at` is inside it; a tie takes the earlier one). The line gives the whole uncut run. The cut is the middle frame of the uncut run when that frame is in the asked range; else it is the frame of the asked range nearest to that middle. So the cut is always in `at - window ..< at + window`: an agent places an edit at the cut, and a long silence that starts near the window edge must not move the cut far from `at`. With no silence, the result is the middle of the quietest window of the asked range and its level, marked as no pause. No reference tool documents this search (research finding 31); the tester searched the lowest RMS near the time.
- **Faults.** `silences` and `nearest_pause` give edit points, so they never read a fault as silence. Before the scan, they run the export media check (`checkMedia` with an `ExportSource` of the asked range and the track list) on `Session.ignoringMuteAndSolo`, the session that `mixLevels` reads, so a missing file on a muted track counts. A fault refuses the read with the file names: `<files>; its clips would read as silence, so the read gives no silence or pause. Restore the file, or read a range or tracks without it.` After the scan, a file that the scan could not read (a clip past the asked range that the edge rule read, or a file that changed during the read) refuses the read with the same text. `meter` gives no edit point: it reads a fault as silence and puts its warning lines first. On an open session, `Studio.readMix` gives `ReadWork.read` the window session, and `ReadWork.read` runs the same check on `ignoringMuteAndSolo` of that session, not `Studio.exportFaults`, which reads the window session with its flags.
- **Busy and takes.** On an open session, `Studio.readMix` calls `checkIdle()` first. During a take, a take start, a finalize, a level, a duck, an import, or `settle()`, it throws `.busy`, and the tool gives the `AgentBusy` text. A read holds no transport, so it never refuses the Record of the user. A take start ends a running read, as `exportEnd` ends the exports and imports of every window (capture comes first, 0019 and 0040). The read stops at its next block, and the tool gives `Dirigible started a take, so the read stopped.` A read that completed before the take start keeps its result. The close of the window (`settle()`) also ends a running read and waits for its end; the tool gives `The session window closed, so the read stopped.`
- **Meter.** `DirigibleAudio/DSP/RangeMeter.swift` measures the heard stereo mix of `from ..< to` exactly, as a stereo export of that range: integrated loudness (BS.1770, gated), loudness range, max momentary (largest 400 ms block), max short-term (largest 3 s value), true peak (BS.1770 Annex 2), and sample peak. The window grid does not apply to these values; only the step lines use it. A mono track goes to both channels at unity (`MixReader.swift:102-109` reads channel `min(channel, last)` with no pan factor; 0007), so it reads 3.0 LU over the BS.1770 value of the same signal on one channel, and over a mono export (research finding 10). `LoudnessMeter` gets an opt-in short-term series, nil for the live and record meters, so their work does not change.
- **Loudness range.** EBU Tech 3342 (research finding 12): the short-term values of the full 3 s windows inside the range, one for each 100 ms from `from` (the first ends 3 s after `from`); the absolute gate -70 LUFS, then the relative gate 20 LU under the power mean of the values over the absolute gate; LRA = P95 - P10. Pp is the value at index `round((n - 1) * p / 100 + 1)` (1-based, half away from zero, as Swift `.rounded()`) of the sorted gated values: the Tech 3342 MATLAB code. Probe P4 of the run gives the hand values: Tech 3342 cases 1 to 4 read 10, 5, 20, and 15 LU, and 90 s at -30 dBFS then 10 s at -20 dBFS reads 10 LU (2.79 LU with P90). `RangeMeter` gives a range for any range with one full 3 s window. A value with no data is none: under 400 ms, max momentary; under 3 s, max short-term and the range; silence, all loudness values.
- **Range of short content.** `meter` prints `range none (under 2 min)` for a range shorter than 120 s. EBU R 128 s1 says that LRA does not apply to short-form content of up to about 2 min (research finding 16). The rule is in `ReadWork.meterLine`, so `RangeMeter` stays testable on the 40 s Tech 3342 cases. Reverse: remove the rule from `ReadWork.meterLine`, and print the range for any range with one full 3 s window (Tech 3342 sets no minimum, finding 13).
- **Units and defaults.** Frames everywhere. Threshold -40 dBFS (the duck default). Minimum length 500 ms for `silences` and 200 ms for `nearest_pause`; window 2 s. A `step` is a multiple of the 50 ms window; the steps start at the first grid window of the range.
- **Texts.** `DirigibleMCP/ReadWork.swift` is the one owner of the argument rules and the texts of each command and its tool (0041, 0049):
  - `silences`: one line `<start>\t<end>` for each silence, at most 1000, then `<n> more silences: give a shorter range or a longer min_length.`; `No silence.` when none.
  - `nearest_pause`: `pause\t<start>\t<end>\t<cut>`, or `no pause\t<cut>\t<level> dBFS`.
  - A level column (the level of `no pause`, the RMS and the peak of a step line) has one decimal, a sign over 0, and `dBFS`. Digital silence is `-inf dBFS`, so a script reads each level column as a number and a unit. `none` is only in the values of the `meter` line, where it means no value.
  - `meter`: first the warning lines of a stereo export of the range: the unread files (`ExportText.faultLines`: their clips read as silence), then the tracks that are not heard (`ExportText.unheardLines`, 0039). Then `heard stereo mix: loudness <I> LUFS, range <LRA> LU, max momentary <M> LUFS, max short-term <S> LUFS, true peak <TP> dBTP, peak <P> dBFS`, each value with one decimal and a sign for a dB value over 0, or `none`, and `none (under 2 min)` for the range of a short range; with `step`, one line `<start>\t<RMS> dBFS\t<peak> dBFS` for each step. A step count over 1000 is refused before the read. The `meter` tool description, the command help, and the guide say that it measures the heard stereo mix, as a stereo export.
  - `silences` and `nearest_pause`: a fault refuses the read (Faults). Their one warning line, first, is for a silence that reaches the edge limit and can go on past it: `Warning: a silence can go on beyond frame <frame>, the read limit 60 s outside the range; its line stops there.` The frame is the start or the end of the line of that silence.
- **Commands and tools.** `dirigible silences`, `dirigible nearest-pause`, and `dirigible meter`; tools `silences`, `nearest_pause`, and `meter` (0041 name rule), read-only, no lock, long tools with progress and cancel (0049). On an open session, `liveJob` runs them through one `Studio.readMix` on the window session.

## Consequences

- F96 builds its review list on `LevelSeries.silences`, so the list and the agent read give the same pauses.
- A read of a whole 66 min session takes seconds (budgets of `ReadBenchmark`, optimized, on 66.5 min of 2 stereo tracks: `silences` 2.5 s, `nearest_pause` 0.5 s, `meter` 10.5 s, each 2 times the first optimized time rounded up to 0.5 s); `nearest_pause` reads 2 x window, plus the length of a silence that crosses an edge of it, at most 60 s past each edge.
- The texts are a contract for agents and scripts: a change of a column is a change of this record.
- `silences` and `nearest_pause` ignore mute and solo, as the duck. `meter` measures the heard stereo mix, so `meter` of the whole session equals the loudness measure of a stereo export.
- A ranged duck reads the frame 0 grid, so its run edges can move by less than one window (50 ms) from those of the scope-start grid. A duck of the whole session keeps its runs.

## Alternatives considered

- **A per-sample rule as ffmpeg `silencedetect`** (each sample under the threshold). Rejected: one click ends a pause, and it is not the duck rule.
- **The heard tracks for `silences` and `nearest_pause`.** Rejected: a pause search must not change when the user mutes a voice to listen, and the duck already ignores the flags.
- **Mute and solo off for `meter`.** Rejected: its numbers would not be those of the export, and 0039 says that the loudness meter follows the flags. Hindenburg measures the heard mix.
- **A fixed margin of `minLength` past each edge.** Rejected: a silence longer than the margin across a page edge would get two different extents on two pages.
- **A grid from the range start.** Rejected: two reads with different `from` values would disagree on the same pause.
- **Nearest rank for the LRA percentiles.** Rejected: the Tech 3342 MATLAB code gives the index rule. On the cases of probe P4 both give the same values.
- **Times in milliseconds** (the tester proposal). Rejected: every tool takes frames.
- **A `--mix` mode of `dirigible loudness`.** Rejected: one command with two output shapes; `loudness` stays per clip.
- **JSON output.** Rejected for now: every audio tool gives text lines; `info --json` is the only JSON read.
