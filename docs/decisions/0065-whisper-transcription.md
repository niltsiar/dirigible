## Context

F112 (R7) and the user decision of 2026-10-15 (backlog item 0331): transcription in the app with whisper.cpp, vendored as LAME is (0034), so it runs on every supported macOS version. Facts (`docs/research/whisper.md`, F-numbers):

- whisper.cpp v1.9.5 (2026-10-06), ggml 0.26.0, MIT, C11 and C++17 (F1, F2). It has no `Package.swift` since 2025-03 (F6). v1.9.3 to v1.9.5 have no XCFramework (F8).
- A CPU build needs 62 to 73 files, 4.2 to 4.6 MB (F3). The x86 and arm `quants.c` define the same symbols (F5). `ggml-version.h` and `WHISPER_VERSION` are made by CMake, so the target supplies them (F4).
- ggml gets AVX2, FMA, and F16C only from compiler macros, and `Package.swift` cannot set `-mavx2` per arch: the x86_64 slice builds at the SSE4.1 baseline (F11 to F13). Accelerate BLAS takes the large matrix products (min batch 32, `ggml-blas.cpp:420`).
- Metal on Intel GPUs gives wrong output in reports, and SwiftPM treats `.metal` as an Xcode resource (F9, F10, F16).
- Models: base 147,951,465 bytes, small-q5_1 190,085,487 bytes, large-v3-turbo-q5_0 574,041,195 bytes, pinned at Hugging Face revision `5359861c` with SHA-256 values (F18). Spanish WER: base 9.9 (Fleurs), small 5.6 (F30).
- No word API: the caller joins tokens (F25). VAD (Silero, 885,098 bytes) removes silence, the main cause of hallucinations (F28, F29).
- The DMG is 19.2 MB, and the Telegram post has a 50 MB limit.
- `Studio.blockingRun` holds the write chain for its whole work. A job on 1 h of audio takes minutes (F21).

## Rubric

1. Runs on macOS 14 and later, Intel and Apple silicon, with no permission prompt.
2. Keeps the 0034 rules: source in git, warnings fixed at the cause, no unsafe flag.
3. The DMG stays under 30 MB.
4. An edit during a job is never lost, and the words land on the right audio.
5. The fewest new public seams, each with a test.
6. Speed on this Intel Mac (C17).

## Shape inside V1

- **D1 Target.** `Sources/CWhisper`: `src/whisper.cpp`, the ggml core, `ggml-cpu` (with the `arch/x86` and `arch/arm` files behind wrapper files that include each one under its arch macro), and `ggml-blas` with Accelerate. `include/` holds `whisper.h` and the ggml headers. `cSettings` and `cxxSettings`: `.define("GGML_USE_CPU")`, `.define("GGML_USE_BLAS")`, `.define("GGML_USE_ACCELERATE")`, `.define("GGML_BLAS_USE_ACCELERATE")`, the version defines, `.headerSearchPath(...)`, `.treatAllWarnings(as: .error)`. `linkerSettings: [.linkedFramework("Accelerate")]`. `cxxLanguageStandard: .cxx17` on the package. No Metal, no Core ML. The define list follows `ggml/src/CMakeLists.txt` (F4).
  - Patch (`README.dirigible`): the XCBuild path of `bundle.sh` adds `-Wshorten-64-to-32`, which gives 530 sites (523 on x86_64, 526 on arm64); each path gives 25 `-Wambiguous-macro` sites. Each shorten site gets a cast of the whole expression to its target type, under the invariant of its group: each tensor of a CWhisper graph has fewer than 2^31 elements and bytes (the largest weight, the large-v3-turbo-q5_0 token embedding, has 66,388,480), or a local bound (at most 448 tokens, at most 9,600,000 samples in a 10 min piece). `MIN`, `MAX`, and `static_assert` get the token text of the SDK macros, so the two visible definitions are the same. The 5 upstream `diagnostic ignored` pragmas go: they ignore `-Wpedantic`, `-Wunused-local-typedefs`, and `-Woverlength-strings`, and the compile command of the real build enables none of the three. A compile of the four files with the full flag set of the build and `-Werror`, with the pragmas removed, gives 0 warnings, and so do the three strict builds. `src/aneforge/whisper-aneforge.cpp` is excluded, and the patch removes the `ANEFORGE_ENCODER` read and the aneforge calls of `whisper.cpp` the `GGML_BACKEND_PATH` read of `ggml-backend-reg.cpp`, and the `GGML_BACKTRACE_LLDB` read of `ggml.c` (the fork and exec of a debugger). The abort patch (83 lines added, 15 changed, in `whisper.cpp`) wires `params.abort_callback` into the ggml graph compute of the encoder, the decoder, and VAD, and adds abort checks in the VAD window loop (every 32 windows), the mel frame loop (every 32 frames of thread 0), and `get_signal_energy` (every 65,536 samples). The scheduler overload of `ggml_graph_compute_helper` has no abort parameter in v1.9.5 (`whisper.cpp:196-216`), so without the patch a stop waits for the running window. Two files of our own, `cwhisper_stop.c` and `include/cwhisper_stop.h`, hold the `atomic_bool` stop flag and the abort callback that reads it (D6). They are not part of the patch.
- **D1b x86 SIMD.** The x86_64 slice builds at the SSE4.1 baseline, because the baseline meets the speed rule on this Intel Mac. A future speed miss can add `#pragma clang attribute push(__attribute__((target("avx2,fma,f16c"))), apply_to = function)` and the three macros under `#if defined(__x86_64__)` in the wrapper files of `ggml-cpu`, after a check that every macOS 14 Intel Mac has these features.
- **D2 Model.** `WhisperModel` is a closed catalog: `base` (default), `small-q5_1`, and `large-v3-turbo-q5_0`, and an internal entry `tiny-q5_1` that only the tests use, for the push guard of the abort patch (C10, C18), each with the file name, the byte count, the SHA-256, and the pinned URL. The model folder is `DIRIGIBLE_MODELS_FOLDER` when it is set (the tests, the verify copy), else `~/Library/Application Support/Dirigible/Models/`, as `DIRIGIBLE_LOG_FOLDER`. `WhisperModel.checked(at:)` checks the byte count and the SHA-256 of one file against its catalog entry and gives a `CheckedModel`, the only input that `WhisperEngine` takes. `checked(in:)` runs it on `<folder>/<file name>`. So each model load (the app job, the CLI, the tool) checks the file before `whisper_init`. A model file of the user reaches `whisper_init` only through the check of D8.
  - Store: `WhisperModelStore` has the model folder and a loader: a closure that gives the chunks of a URL as an `AsyncThrowingStream<Data, any Error>`. The live loader uses `URLSession`, and `WhisperModelStore.swift` defines it, so C5 finds one file. A test loader reads a `file://` URL and can hold before a chunk until its stream ends. The store downloads to `<file name>.download` in the folder, excluded from backup, runs `checked(at:)` on that file, and only then renames it to `<file name>`. The job runs `checked(in:)` again on the final file before the engine (D5).
  - Stop: the store takes a stop check. It reads the check at each chunk, and at least every 0.25 s while it waits for a chunk. A set check ends the stream (the live loader cancels its request), deletes the temporary file, and throws. A partial file never has the catalog name, so no load reads it. The next start downloads again from byte 0 (a resumed download is later item 1162).
  - Leftovers: `removeLeftovers()` deletes each `*.download` file in the folder. Each job start calls it before the download or the check, so a file that a crash or a force quit left goes at the next job. The app has one job at a time and the CLI downloads nothing, so no other writer uses these files.
  - The app job gets the store from the `CaptureEnvironment` field `modelStore` (live: the folder above and the `URLSession` loader; tests: a temporary folder and a `file://` loader). The VAD model ships in `Contents/Resources`.
- **D3 Audio.** A job reads the distinct file spans of the clips of one track: each `offset ..< offset + length` in the frames of the root of its file (0057 D11), merged per root file when they touch or overlap, in the order of the first clip of each span on the track; each root frame reads from the file of the first clip that plays it, so a render and its root never both give a frame; converted to 16 kHz mono float in pieces of at most 10 min for each track length, each cut at the nearest pause (0062). The job reads and converts one piece at a time, so the samples in memory are those of one piece.
- **D4 Words.** The engine gives words in piece time. `SpanMap` turns each word into a file and a file frame range (midpoint rule). Core gets one new public edit: `Session.addTranscript(_ words: FileWords, name: String, derived: [(source: FileID, derived: FileID, span: Range<Frames>)])`. `FileWords` is a list of words in the order of the concatenated spans, each with its file and its file frame range, with no number field: the list position gives the number. `addTranscript` numbers the words from 1 in that order, drops the words of a file that is not in the pool with a count, and a dropped word uses up its number, as a skipped unit of the import does. Then it calls the one internal function that also ends `importTranscript` (0055), in this order: the new `TranscriptID`; the drop of the transcripts that did not load; the insert of the new transcript; for each entry of `derived` whose derived file is in the pool and has no origin (a split stereo file), in list order, `copiedWords(from:span:transcript:)` of `Session+Origin.swift` limited to the new transcript ID; last, the drop from each other transcript of the old anchors in the span of the new anchors of each file, the derived files included. `copiedWords` reads the anchors of an inserted transcript, so the insert comes before the copy; `importTranscript` passes no entry, and the order gives it the result of today. `copiedWords` gets an optional transcript filter; `addDerivedFile` passes none and copies each transcript, as now. A word of a rendered file goes to the root of its chain, in root frames, and a derived file with an origin gets no copy (0057 D11). When no word is kept, `addTranscript` gives no ID and changes nothing (0055 drops a transcript with no word). A copy keeps the number of its source word, clamps it to the span, and moves it by -(span start). The job in DirigibleAudio builds no `Anchor` (internal, Transcript.swift:62). It needs no format change.
- **D5 Job.** `Studio.transcribe(track:language:model:agent:progress:)` has three stages: the start turn on the main actor, the work off the main actor and outside the write chain, and the end turn on the main actor.
  - Refusals: `.busy` during a take, a pending take, or `settle()`, when a job runs in this or any other studio, and when any other studio records, has a pending take, or starts a take (`otherStudios()`, on the main actor): the `exportEnd()` closure of a take start covers only the work that ran when the take start began. So the app has at most one job and one `whisper_context`.
  - Start turn: in the main-actor turn of the refusals, with no `await` after them, the job takes a snapshot of the session, adds its `ReadRun` to `readRuns`, and begins its activity, as `readMix` does (`Studio+Read.swift`). So the run is in `readRuns` before the download, the model check, and the engine, and the `exportEnd()` of each later take start sees it.
  - Work, in this order: `removeLeftovers()` and, when the model file is missing, the download (D2), with the stop check of the run, in a `@concurrent` function off the main actor, as `levelClips`; then `WhisperModel.checked(in:)` and the `transcribe` closure (D6) on one `.userInitiated` GCD thread, never on the main actor (CODING_STANDARDS Concurrency, Isolation). The job reads the stop flags after the check and before the closure call, so a stop during the download or the hash never calls the closure.
  - Stops: the job is a read run from its start turn, so `exportEnd()` ends it at a take start of this studio or of any other studio, and `settle()` ends it (`endReads(.close)`) and waits for it (`readsEnded()`). Neither function changes. The `ReadRun` stays in `readRuns` until the end turn ends, and leaves it at each exit with the waiters of `readsEnded()` resumed, as `readMix` does; else `settle()` waits forever. A take start never waits for the job: it sets the flags, the download reads them (D2), and `abort_callback` reads the `StopFlag` of the `ReadRun` (D6), which `endReads` sets. A cancel (banner, task) sets the same flag. A stop during the download deletes the temporary file (D2). Then the job writes nothing.
  - Activity: from the start turn to each exit, the job holds `beginActivity([.userInitiated, .idleSystemSleepDisabled], reason: environment.transcribeReason)`, as `blockingRun` does (0040).
  - Render during the job: the Studio keeps the list of `(source file, derived file, span)` of each `splitStereo` that commits in its window while the job runs, in commit order (the session stores no provenance, 0054). The end turn passes the list to `addTranscript` as `derived` (D4), which copies the new words to each mono file in the pool with the numbers of their source words. Only the words of the new transcript copy. A render (`repoint`) during the job keeps no entry: its file has an origin, so the new words stay on the root and show under the rendered clips through the origin offsets (0057 D11).
  - End: after the closure returns and the field `transcribeWorkDone` of `CaptureEnvironment` runs (as `clipRenderWorkDone`, so a test starts a take there, C11 c), the end turn reads the stop flags. A set flag decides the exit: a take start throws `.transcriptionYielded`; a cancel or a window close throws `.transcriptionCancelled`. When the flags are clear and `checkIdle()` refuses (a level, a duck, an import, a paste, a split, a render, a placement, or a take start of this studio runs), the turn waits 10 ms in a task of its own, as the finalize wait of `record` does (`StudioTake.swift`). Then it reads the flags and the idle state again, and repeats until a flag is set or the studio is idle (`CODING_STANDARDS.md`: check the guard again after each `await`). The wait is not `await serialized {}`: `TurnQueue.wait` returns with no suspension when no turn is ahead, and `blockingRun` sets `.idle` only after its turn ends and its task resumes (`Studio+Import.swift`), so that loop spins on the main actor after each import, paste, split, or render turn. In a task of its own, the sleep does not throw at once after a cancel of the caller, so the loop does not spin then either. When the flags are clear and the studio is idle, the turn applies `addTranscript` to the current `session` through `recordEdit` (`history.edit(agent:)`, then `scheduleSave()`, the steps of `edit` after its busy check), with no `await` between the last flag read and that edit. So the whole state change comes before the first `await` (`CODING_STANDARDS.md`). The job never writes `session = changed` after an `await`, so an edit that another caller makes during the save stays, with its undo entry. The `ReadRun` leaves `readRuns` after the edit. Then the job waits for its save turn (`await serialized {}`) and returns the report, so a caller and a test read the package after the save. A save failure sets `saveError`, as for each edit.
- **D6 Seam.** No protocol (CODING_STANDARDS Design, 0013 Test seams): the seam is the closure field `transcribe` of `CaptureEnvironment`. It runs the engine part of one job: it gets the `CheckedModel`, the `WhisperLanguage`, the piece count, a function that reads piece n as 16 kHz mono float, the `StopFlag` of the job (the stop check), and the progress, and it throws `TranscribeError` or returns a `Transcription`: the `TimedWord` values of each piece in piece time and the language. With `.automatic`, the language is the code of `whisper_lang_str(whisper_full_lang_id(ctx))` after the first piece that gives a word, and each later piece gets that code. The live value makes one `WhisperEngine` (one `whisper_context`) for the job and runs the pieces in order; tests give a scripted closure. The `StopFlag` is a Swift class that owns one `atomic_bool` of `cwhisper_stop.c`. The `ReadRun` makes it with the run and frees it with the run, and the engine passes its callback and its pointer as `abort_callback` and `user_data` for each whole `whisper_full` call of a piece (D7b). The engine reads the flag before each piece: a set flag returns a stop with no `whisper_full` call. After each `whisper_full` call, one pure function maps the return code and the flag to a result: a non-zero code with the flag set, and code 0 with the flag set, are a stop; a non-zero code with the flag clear is a `TranscribeError` (after a second call, the first pass stays, D7b); code 0 with the flag clear is the result. The value types are in `Transcribe/Transcription.swift`. The engine sets `whisper_log_set` and `ggml_log_set` once per process in a `static let` before the first `whisper_init`, as 0034 Init does for LAME.
- **D7 Word ends.** Token end times of whisper.cpp miss C24 in every setting (probe: largest error 0.40 s to 0.90 s): a punctuation token takes the next pause, and with VAD the token times in the compressed audio are early, so the time map puts some words in the segment before them. After the token join of each piece, the engine moves each word end to the start of a pause of the piece samples: the pauses are runs of 10 ms frames under max(-40 dBFS, noise floor + 6 dB) of at least 0.20 s, and an ordered alignment, in a band of +/-1.0 s round each token end, gives each pause to at most one word (a word that ends in punctuation prefers a pause). A word with a pause ends at the pause start. A word whose previous word took a pause starts at the end of that pause; any other word keeps its token start. A word with no pause keeps its token end. `WordEnds` owns the contract that each word it returns has start < end, never a zero length, in one pass in time order: a word whose moved end is not after its start keeps its token start and token end and gives its pause back (the next word then keeps its token start, and is checked again); a word that still has end <= start (an empty token interval) takes as its end the start of the first 10 ms frame under the floor after its start, capped at the next word start, at start + 1.0 s, and at the piece end, and start + 0.01 s only when the cap is not after the start. In the same pass, a start before the end of the word before it moves to that end, and an end after the next word start moves to that start, so in one piece each end is at or before the next start. The probe meets C24 on 8 token dumps (4 clean, 2 at -55 dBFS, 2 at -45 dBFS) with 0 inverted words in 160. The clean and -55 dBFS dumps share the -40 dBFS floor rule of the truth, and the rule was tuned on the 8 dumps, so they show that the rule works on them and no more. Held-out (i), noise at -35 dBFS (floor -22.5 dBFS; end error 0.027 s mean, 0.102 s largest), is the evidence that is independent of the floor rule. Held-out (ii), a second voice (0.005 s, 0.009 s), is evidence for a second voice only: it has no noise, so its floor and its truth share the -40 dBFS rule. Both ran once after the rule was frozen, with 0 inverted words.
- **D7b Thin segments.** The decoder of whisper.cpp can skip speech inside one 30 s window. The skip depends on the whole piece (one log-mel and the carried prompt), and the skipped speech shows as a thin segment: few words over a long time. In piece 2 of a tester episode, the segment 103.91 s to 116.45 s holds 10 words (1.254 s per word), and the 153 other segments hold at most 0.56 s per word; a fresh call on 103.45 s to 117.20 s gives 29 words. So after the first call of a piece, `WhisperEngine` decodes each thin segment again (`ThinSegments`):
  - A segment is thin when it lasts 5.0 s or more, with more than 1.0 s per word. A word belongs to the segment of its first token with a letter or a digit.
  - The span of a thin segment runs from the end of the segment before it (the piece start for the first segment) to the start of the segment after it (the piece end for the last). Spans that overlap or touch make one call. A piece makes at most 4 second calls: the calls with the most first-pass words first, ties in time order. A first-pass language with no spaces between words (`zh`, `ja`, `th`, `lo`, `km`, `my`, `bo`, `yue`) gives no call.
  - The second call is a fresh `whisper_full` call on the samples of the span (160 samples per tick, clamped to the piece), with the params of the first call (the `abort_callback` and the progress of the job) and the first-pass language as a code. Its words move by the span start. `ThinSegments.redecode` runs the second calls of a piece through a `decode` closure (the closure seam of D6, no protocol): it gets the sample range and the language code, and the engine passes its `whisper_full` call. Tests give a scripted closure.
  - The second-pass words replace the first-pass words of the thin segments only when they are more, have at most 6.0 words per second over the thin segments, are not thin over the same time, and have no n-gram of 1 to 8 words that comes 3 times or more back to back over 6 words or more. Else the piece keeps the first pass.
  - The merge removes the first-pass words of the thin segments of the call and puts all second-pass words of the call there, as one block in call order, also a word on or past the span end. At the start of the block, it drops the longest run of at most 4 second-pass words whose texts (case, punctuation, and accents ignored) equal the last first-pass words before the thin segments, when the two runs end 1.0 s apart or less. At the end of the block, it drops the mirror run: the texts equal the first first-pass words after the thin segments, and the two runs start 1.0 s apart or less. The rule compares the ends at the start edge because with VAD a first-pass word can start long before its speech (16.50 s against 43.32 s in a trial track). `WordEnds.place` (D7) runs once, on the merged words.
  - A stop during a second call stops the piece, and no later call runs. A failed second call keeps the first-pass words, and the next call runs. The piece language is the first-pass language.
  - Each second call that ends writes one journal note `transcript redecode`: `start` and `end` (the span in piece ticks), `before` (first-pass words of the thin segments), `after` (second-pass words that the edge rule of the merge keeps, also when the accept test refuses them), `kept` (`first pass` or `second pass`), and `fault` (the return code of a failed call, which has no `after`). A stopped call writes no note.
  - On 10 tracks of the trial excerpts, the rule finds 24 thin segments in 17 calls, and the accept test refuses each of them, so no first-pass word changes. The second calls cost 0.04 to 0.21 times the first pass on 6 of the 8 tracks with a call (median 0.14), and up to 2.25 times on a guest track with short replies.

## Job candidates (design it twice)

- **A (chosen): file spans and file words.** D3 to D5. An edit during the job keeps its place (C8), because the words anchor to files that never change; a split during the job moves clips to mono files, and the end turn (D5) gives their list to `addTranscript`, which copies the new words to them (D4); a render during the job moves clips to a file with an origin, and the new words stay on the root (0057 D11). A duplicated region is read once (C6), gaps are not read, and clip gain and fades do not change the audio of the engine.
- **B: a timeline render of the track and `importTranscript`.** It reuses the import with no Core change, but it reads gaps and duplicates, and an edit during the job moves the words to the wrong audio unless the job holds the write chain (`blockingRun`) for minutes. Rejected on rubric items 4 and 6.

## Synthesis decision

Base: A, because each part has one owner: the files own the audio, Core owns the anchor rules, and the job owns only time. From B, A keeps the import report line (kept, skipped, untimed) and the CLI text of `transcript import`.

- **D8 User model file.** A ggml whisper model file of the user passes two layers before a job loads it.
  - Parse: `WhisperModelFile.read(_:)` is the boundary type. It reads the header, the mel filter header, the vocabulary, and each tensor header with seeks, and of the tensor data only `decoder.positional_embedding`, which must have no NaN and no infinite value. It refuses each input class that a header shows and that ends the process in the loader or in `whisper_full`: the hparams outside the bounds of the OpenAI models (README.dirigible, Invariant T), an unknown ftype, an n_fft other than 201, a vocabulary count outside 1 to n_vocab or with no token " ", and a tensor walk with a bad type, dimension, or name, a name twice, or a sum that is not the file size.
  - Helper: a parse cannot find each bad file (corrupt weights stop at a C `assert` in `whisper_full`), so `dirigible model check <path>` loads the file in a helper process. `ModelFileCheck.helperMain(path:)` installs handlers that turn SIGABRT, SIGSEGV, SIGFPE, SIGBUS, SIGILL, and SIGTRAP into `_exit(128 + signal)`. Then it runs the parse, the SHA-256 of the file, and a trial: `WhisperEngine` with no VAD and the `whisper_full` params of the job on 1 s of seeded noise, language `en`. With the VAD of the job, the noise runs no decoder and a NaN file passes. A pass prints one line with the SHA-256 and the facts and exits 0. A refusal exits 1 and prints one line on stderr: `Refusal: <code>` for the path `-` (a kind, and for a reason with a value, a space and the value), else `Error:` and the English text. The app maps the code (`ModelFileRefusal`) to its own language tables (decision 0010); a helper that gives no code shows its English line. The helper of the app is `Contents/Helpers/dirigible`: an ad-hoc signed copy with the quarantine value of a download and the approved flag of Open Anyway starts it, also when the helper file keeps the flag of a download (probe on macOS 15.8.1). The CLI and the MCP server use their own executable. A helper death shows no dialog and leaves one `.ips` report in `~/Library/Logs/DiagnosticReports`. The helper exits when its parent process exits, so an app crash or a Force Quit leaves no trial that runs beside the next take.
  - Hash binding: `ModelFileCheck.run(_:helper:passed:stop:)` hashes the file and gives a `CheckedModel` only when the helper exits 0 and prints the same SHA-256. Another SHA-256 gives `.changedDuringCheck`; a signal, or an exit of 128 + a handled signal, gives `.helperStopped`; a `Process.run()` that throws gives `.helperNotStarted`, a fault of the install and not of the file. A `CheckedModel` has a source: a catalog entry (D2) or a user file with its `PassedModelFile`, the SHA-256 and the facts of the pass. `WhisperEngine` still takes only a `CheckedModel`.
  - Kept SHA-256: when the SHA-256 of the file equals the one of the `PassedModelFile` that the caller keeps, and the record has the check version of this build (`ModelFileCheck.version`), no helper runs and the facts come from the record. A change of the parse, the trial, or the CWhisper build that can change what passes increments the version, so the first job after an app update runs the helper again.
  - Reads: `run` opens the file once (`OpenModelFile`). Only a regular file opens: a FIFO, a device, or a folder gives `.unreadable(EFTYPE)` before any read. The hash, the helper, and the engine read that one open file with `pread`, so a rename over the path after the open cannot give them other bytes. The helper gets the open file as its standard input (`dirigible model check -`). `WhisperEngine` loads a user file through a `whisper_model_loader` (`ModelFileLoad`) that hashes each byte that whisper.cpp gets, and compares that SHA-256 with the record before the first use of the context: other bytes (a write into the file after the check) give `.modelChanged`, and the context is freed. The job reads the file two times with a kept SHA-256 (the hash and the load), and the helper reads it two more times. The loader reads the magic and the 11 hparams (48 bytes) before the load, because whisper.cpp aborts on zero hparams. After byte 48, a stop of the job or a read error gives zeros and eof to whisper.cpp, and the load ends with no abort (probe of the run, 2026-11-01): it throws `.modelLoad` or `.modelFile(.unreadable)`. A catalog model loads from its path (D2).
  - Stop: `run` runs on the job thread, never on the main actor. It reads the stop check before each 1 MiB chunk of the hash, before the helper starts, then every 0.25 s while the helper runs. A stop sends SIGTERM, then SIGKILL after 0.5 s, and `run` returns `.stopped` after the helper is gone. The hash of a kept file at the sheet open (`Studio.hashModelFile`) and the sheet check are read runs with the same stop check. A stop cannot end one `open` or `pread` that blocks in the kernel (a share that stops answering, a dataless iCloud file). So these runs are not joined: `settle()` sets their stop and does not wait for them, and a result that arrives after the close is dropped with `.readClosed`. The runs of the package files keep their join.
  - The C asserts of the trial exist only in a build with no NDEBUG. The helper and the app engine come from one CWhisper build, so both keep or drop the same asserts.
## Consequences

- The app makes its first network call, only for a model download. The guide says so.
- The x86_64 slice can be slower than a CMake build with `-mavx2`.
- A whisper.cpp update reapplies the patch of `README.dirigible`, and checks the define list. The casts come from the clang source ranges of the warnings, so a script makes them again; each new site needs a group with an invariant.
- No shipped code path loads a dylib from an environment variable: the ANEForge encoder of whisper.cpp (`ANEFORGE_ENCODER`, `ANEFORGE_DYLIB`, Apple silicon) and the `GGML_BACKEND_PATH` backend load are out. `ggml_backend_load` still exists, and no code of the app calls it.
- Known limits of the word end step (measured in the run probe). (1) On connected speech, a pause that whisper does not mark can go to the next word that ends in punctuation (1 of 11 moved ends in C14): whisper writes "7," after a pause that comes before "seven", and the end of "7," would move 0.37 s before its start. The word keeps its token times, so 0 words of the 4 C14 dumps end before they start (the first version gave 3), and the pause stays unused. A start guard in the cost fixes the pause but fails C24 on two dumps. (2) Run-on speech, with less than 0.20 s of silence between words, has no pause: the ends are the token ends, with an error of 0.095 s mean and 0.420 s largest with VAD, and 0.539 s and 1.083 s without (held-out (iii): 20 words with gaps of 0 to 50 ms, 1 pause found). C24 does not hold there, and the guide line for a user who cuts from the text says that a cut at the end of a word in fast speech can keep or lose a part of it. (3) The first word of a piece has no pause before it and keeps its token start (0.49 s early without VAD in held-out (i)). (4) A word that still has end <= start (an empty token interval) gets its end from the audio level only: the first quiet frame after its start, at most 1.0 s later or at the next word start. A cut at it can leave the rest of a word that is longer than the cap, or keep up to 1.0 s of a sound that follows with no pause; when the cap is not after the start, the end is start + 0.01 s and a cut leaves the word audible. It fired 2 times in 18 dumps ("con" in C14, "Harbor," in held-out (iii)) and 0 times in the 8 C24 dumps and in held-out (i) and (ii). Later item 1399 is a richer word alignment.
- `ggml_print_backtrace` ignores the `GGML_BACKTRACE_LLDB` variable on Apple: an assert prints the native backtrace and forks no debugger.
- The source adds about 4.5 MB to git.
- A `GGML_ASSERT` failure aborts the app, also a take in another window, as a LAME assert does (0034). A model file reaches `whisper_init` only as a `CheckedModel`, from the catalog check (D2) or the user file check (D8), and each NaN or infinite sample is set to 0 before `whisper_full`. A take start in any window ends the job (D5), so a job does not run during a take.
- A take start does not wait for the job: the whisper threads stop at the next abort check, and a download reads the flag at least every 0.25 s (D2). The abort patch (D1) puts a check in the encoder, the decoder, VAD, the mel, and `get_signal_energy`: the probe stop times are at most 0.222 s against the C10 bound of 2 s. A non-zero `whisper_full` return code with the stop flag set is a stop, not an engine error (codes seen: -6, -3, -9). The abort callback reads one lock-free `atomic_bool` of our own in `CWhisper`, with no lock, no allocation, and no actor hop. It runs on the caller thread of `whisper_full` only: ggml calls it when `state->ith == 0` (`ggml-cpu.c:3150-3151`), and thread 0 is the caller thread (`ggml-cpu.c:3452-3453`); the worker threads of `ggml-cpu.c:3369` never call it. The flag is atomic because the stop sources (a window close, a take start, a banner Cancel) run on other threads, and the callback runs once for each graph node.
- The abort patch costs about 5 % more time without a stop (an upper bound: the probe callback appended to a list under a lock for each call, 5.52 s against 5.23 s on the C14 Spanish fixture). A future whisper.cpp upgrade must carry this patch, or a stop waits for the running window again (2.2 s at 30 %, 11.5 s at 0 % of 600 s with VAD). The push guard in `WhisperEngineTests` (tiny-q5_1, about 120 s, VAD on, flag set first, a stop within 5 s in debug) fails a source that lost the patch of the VAD stage; a loss of the encoder or decoder part fails the 2 s bound of the engine bench. The engine accuracy and word-time cases (C13, C14, C15, C24) and the 2 s stop bound assert only in `WhisperEngineBenchmark` (decision 0028 exception, logged in the run): a run that changes `Sources/CWhisper` runs the engine bench in Phase 7 (`make bench FILTER='WhisperEngineBenchmark TranscribeBenchmark'`, after `scripts/fetch-whisper-test-model.sh`).
- whisper.cpp and ggml log to stderr by default: the engine routes both log hooks to the journal (0059).
