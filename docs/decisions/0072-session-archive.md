# 0072. Session archive: FLAC clip files with an archive attribute

- Status: accepted
- Date: 2026-11-04
- Accepted: 2026-11-23, after the plan gates of run `2026-11-04-flac-archive`.
- Amends: 0002 (the folder `Archive/`), 0003 (FLAC as the storage form of an archived session), 0011 (two commands), 0017 (the peak pass through `poolFileName`, the cache re-key), 0024 (the formats table), 0051 (the skill line of the archive tools), 0071 (the archive holds the raw sweep; the sole-copy predicates read the clip file through `poolFileName`; the gate keeps the CAF of a clip in FLAC), 0075, 0079, and 0081 (a copy out of an archived package writes WAVs; the Favorites store is never archived).

## Context

A tester archives finished sessions by hand to save disk space (backlog item 0222, F132). The user asked for four things (2026-10-17): an archived session returns to work at any later time; each sample and each session fact stays; a later build unarchives an older archive; and Dirigible unarchives by itself before an edit, with progress.

The clip files are 24-bit WAV (0003). FLAC holds 24-bit integer samples with no loss. A probe of run `2026-11-04-flac-archive` (`probe-flac/`) converted the 61 clip WAVs of the tester corpus to FLAC and back with the AudioToolbox codec: all 61 are sample-equal. The FLAC files use 0.486 of the WAV bytes (0.231 to 0.537 for each package). The STREAMINFO MD5 equals the MD5 of the WAV `data` bytes. The Apple encoder writes no SEEKTABLE, and 0003 measured a FLAC seek of 0.65 s at minute 28.

No reference editor archives in place (research `archive.md`). Hindenburg PRO has no archive command. Reaper writes a FLAC copy of a project into a new folder. Audacity compacts with a temporary file, a rename, and a delete.

The backups (0043), the undo snapshots, and the clipboard records hold the pool path of each file. A placed segment of 0071 has only its WAV.

## Decision

**State.** An archived session has the root attribute `archive="flac"` in `session.xml`. The writer writes it, with version 22 (`archiveSessionVersion`), only while the session is archived (0024 P6, P7). So an older build refuses an archived package and changes no file in it (P3, P4). Undo, redo, and a revert keep the current value, as for `<recording>` (0003, 0043). A change of only the attribute records no undo entry.

**Names.** A pool path stays `<stem>.wav`. While the session is archived, the file on disk is `<stem>.flac` in the same folder. `poolFileName` (DirigibleCore) is the one way from a pool file to its name on disk: `Clips/<stem>.wav` when an item is at that name, else `Clips/<stem>.flac` when an item is there, else the WAV name, with its form. It opens nothing. Each opener keeps its own open call and its link rule: `openMedia` opens with `open(2)`, the session import and the template copy with `openChecked` (no link at any component, 0075, 0079), and a paste with its clone, copy, or conversion. Each opener opens the other name once on ENOENT; `openMedia` also does so when `AVAudioFile` fails and the name no longer gives the file of its open descriptor. Each job renames its new file before it unlinks the old one, so a read with no lock does not miss a file during a job of another process. Each reader uses it, also the copies into another package and the 0071 sole-copy predicates (`wavBackedSegments`, `soleCopyWAVs`, `rawFiles`, `rawGain`). `scripts/check-clip-paths.sh` fails on a clip path that a reader builds by hand, and on an open call in the import, render, and transcribe code that its allow file does not name; the writers of a new clip and the other opens have allow entries.

**Copy out.** A paste, a favorite add, a paste from the Favorites store, a session import (0075), Save as Template, and a new session from a template (0079) resolve each source file through `poolFileName` and keep its name and form with the copy plan. A source that changes form before the copy pass stops the copy with "source changed". A source with neither name on disk stops it with "source missing". A source file that resolves to a FLAC goes through the conversion path, and the read-back checks that the target is a WAV, so a `.wav` name of the target never holds FLAC data. A copy of an archived session has no `archive` attribute. The source does not change, so Add to Favorites and Save as Template run on an archived window with no unarchive. The Favorites store (0081) is never archived: the archive refuses the store path of its process. A package that was archived under another store path and then becomes the store unarchives in its first store write, with no backup.

**Files.** The archive converts each pool file whose path ends in `.wav` and whose file is 24-bit integer PCM at the session rate, also the WAV of a placed take whose CAF is gone (0071). Every other file stays as it is: a missing file, another format, a stray WAV, the WAV of a WAV-backed unplaced segment (0071), and `Capture/`, `Backups/`, `Transcripts/`, and `Artwork/`. The unarchive converts each FLAC of a pool `.wav` path or of a WAV-backed segment, whatever the attribute says, so no path leaves a clip FLAC that nothing reaches.

**Order.** The core takes the session of its caller and a save closure (as `UnusedFiles.prune(_:save:)`), in a sync form for the CLI and an async form for `Studio`, and sets `archive` in memory with each save. Under the package lock (0012), after the version check and the pending-take refusal:

- Archive: check the disk need, then save `session.xml` with the attribute (no backup). Then, for each file: encode to `.<name>.archive-<UUID>.tmp` in `Clips/`, flush it, decode it in full and compare the MD5 of its samples with the WAV and with STREAMINFO, rename it to `<stem>.flac`, flush `Clips/`, unlink the WAV, and flush `Clips/` again. A job with no file to convert changes no file and saves no attribute.
- Unarchive: check the disk need. For each file: decode to a temporary WAV with the clip writer of `ClipConversion`, flush it, compare the MD5 of its `data` bytes with STREAMINFO, rename it to `<stem>.wav`, flush `Clips/`, unlink the FLAC, and flush `Clips/` again. Then, when the attribute is set, save `session.xml` with no attribute (no backup), at the lowest version that holds the session.
- One bad file never blocks the other files. A source with a decode fault (a read error of the decoder, a read that ends before the STREAMINFO length, or frames or an MD5 that differ from its check) stays in its form, and the report names it as damaged with its decoded frames; the job goes on with the other files. The unarchive then saves no attribute, so edit and Record work with that one clip faulted, and `dirigible file unarchive` exits 1 with one line for each damaged file. The check decodes the whole file: `AVAudioFile` gives the STREAMINFO length of a truncated FLAC with no SEEKTABLE (probe of run `2026-11-04-flac-archive`). A POSIX I/O fault of the volume (EIO and the like), the disk check, a stop, and a cancel keep each file and stop the job. After a crash at any instant, each pool file has a WAV or a FLAC with all its frames. When both files exist, the WAV is read, and the next job checks the other file again before it unlinks it. `removeTemporaryFiles` removes each temporary file of an earlier job at each locked entry (`isArchiveTemporary`, next to `isTemporaryWAV`). Each check reads the file on disk through `AVAudioFile` and needs a length equal to the pool file length before an unlink. After each file step, the job writes the peak cache entry of the new stamp from the entry of the old stamp: the MD5 check proves equal samples (0017).

**Disk.** Each need counts the private bytes of each source file (`ATTR_CMNEXT_PRIVATESIZE`), the bytes that its unlink frees: an APFS clone frees none. A volume that does not return that attribute (HFS+, exFAT) has no clones, so the private bytes there are the allocated bytes. The archive needs the sum of (WAV bytes minus private WAV bytes), plus the largest private WAV bytes, plus `diskMargin` (1 GB) free. The unarchive needs the sum of (WAV bytes minus private FLAC bytes), plus the largest private FLAC bytes, plus `diskMargin`. With no clone, they are the largest WAV plus `diskMargin`, and the sum of (WAV bytes minus FLAC bytes) plus the largest FLAC plus `diskMargin`. A job that does not have the space refuses before any file changes, and names the need and the free bytes. The report gives the bytes freed (the private bytes of each unlinked source) and the bytes written; when the net is 0 or less, it says that the archive freed no disk space. When the net is over 0, it says that an APFS snapshot of the volume can keep them in use until macOS deletes the snapshot. The confirm sheet of the app names the unarchive need as the WAV bytes plus `diskMargin`, an upper bound.

**Capture first (0019, 0040, 0062).** In `Studio` the job is `Transport.archiving(ArchiveRun)`. It refuses with `.busy` while another studio records, has a pending take, or starts a take, and while this studio exports, transcribes, reads, imports, or settles; a play stops first. A pending take of this studio refuses the archive with `.archive(.pendingTake)` and the unarchive with `.busy`. It checks each refusal again after each await. A take start in another studio ends it at the next block, and so does the take disk check when the package of the job is on the volume of the take: the current file keeps its source form. A Cancel, a close of the window, and a quit stop it after the current file; the package keeps the attribute, and the next job ends the conversion. The close of an archived window keeps no backup, so no backup holds the archive version.

**What works on an archived session.** Open, close, the timeline view, the media check, the peaks, `info`, `peaks`, and Unarchive read the FLAC in place. Play, export, and the agent read tools unarchive first, because the in-place read missed its gate. The gate (probe `probe-seek/` of run `2026-11-04-flac-archive`) needs a locate, a scrub, and a play over a six-track session with 200 cuts to read each 0.1 s chunk in 0.2 s or less, and an export of that session in 1.5 times the time of the same export from WAV or less. Result on a MacBookPro15,2 (Intel, 8 logical CPUs, 16 GiB, macOS 15.8.3, load average 14.1 at the start): the play part missed (a locate at minute 110 took 1.83 to 2.37 s, with a maximum of 8.80 s; a scrub took up to 6.73 s; 16 chunks of the play over the cuts took more than 0.2 s, up to 36.4 s), and the export part missed (each FLAC export stopped at its cap of 64 s, against 17.89 s for the WAV: a ratio of 3.58 or more). The same reads from WAV took 0.031 s or less for a chunk under that load. `MixReader` sets the frame position before each chunk read of each clip, so the cost of a FLAC seek follows the position in the file. A FLAC with a SEEKTABLE can pass the gate when the probe runs again, and then `checkReadable` and the read commands change for the kind that passes.

Each job that changes the package unarchives first: an edit, a take, import, paste, a session import, an effect render, a stereo split, a transcription, a level, a duck, a voice match, a ride, a sync, an export preset edit, a silence apply, a prune, a backup revert, undo, and redo. `Studio.checkIdle()` refuses each job that calls it with `.archived`, so a job that no list names fails closed. The read jobs call `checkNotBusy()`: Add to Favorites, Save as Template, and the model file check. Play, export, and the agent read tools add `checkReadable`, which throws `.archived` for both kinds. Remove Unused Files on an archived window unarchives first, then scans, so its list and its move read the WAVs on disk. The app runs the unarchive with a progress sheet and runs a discrete command again after it; a drag, a gain drag, an inspector field, a transcript edit, and an Index or Bins list edit get an alert with Unarchive in place of the replay; Record starts no take after the unarchive. A live MCP call on an archived window gets the typed refusal, runs the same unarchive with progress notifications, then runs the call again once, also a live `record`. In the CLI and MCP, `editPackageCore`, `prunePackage`, and the read commands of an export miss call one step, `unarchiveForWrite`. It runs only when `needsUnarchive` is true: the attribute is set. It converts the pool files of the session before the body and after it, then saves the session of before with no attribute and no backup (an explicit `BackupPolicy.none`, also for a Favorites store, whose policy keeps a backup at each save); the job then saves with its normal backup, so no backup holds an archived `session.xml`. A body that opens or writes no clip file (`touchesClips: false`) runs first, and the step runs only when the body changed the session. A body that opens or writes a clip file, or copies `session.xml` to `Backups/` (a level, a level over time, a duck, a transcription, an effect render, an import, a paste from another package, a session import, a stereo split, a voice match, a clip sync, a favorite add on the store, a backup revert), runs after the step, so its failure leaves the package unarchived with the session facts as before. A prune with no file to drop changes no file.

**Commands.** One File menu item in one slot whose title changes, as View > Show/Hide Inspector: "Archive Session..." (the string table has U+2026, because a confirm sheet follows) and "Unarchive Session". The item is dimmed during a take. A window with an archived state shows the banner "This session is archived as FLAC. An edit unarchives it first." with an Unarchive button, and the subtitle "Archived". After a stop, the subtitle gives the counts of the partly archived state, and the window offers only Unarchive Session, which completes the state. The CLI has `dirigible file archive <package>` and `dirigible file unarchive <package>`; the MCP tools `file_archive` and `file_unarchive` (0011, 0041). Both print the count of converted files, one `Kept:` line for each file that stays, and, for the archive, the freed, written, and net bytes with the no-space or the snapshot text. Both write their progress as `archive: <percent>%` and `unarchive: <percent>%` lines to stderr, and the tools send no progress notification. On a package that a window holds open, the tools give the refusal of `file_prune`. `info` prints an `archive:` line after its header, and its JSON and `session_info` have the key `archive` with the form, the number of FLAC files, and the number of kept pool files. The skill of the agent manual (0051) has one line for the archive tools; the manual core has none.

**Raw sweep (0071).** The archive waits for the sweep jobs of each studio and holds them while it runs. While a clip resolves to its FLAC, `rawVerdict` gives `.archived` and the CAF stays, so no CAF goes before a verified WAV of its take exists.

## Consequences

- An archived tester session uses about half the disk space of its clip WAVs. The 0071 removal and the archive together leave about 1.5 bytes for each sample and channel of a placed take.
- Play, export, and the agent read tools of an archived session wait for the unarchive. The unarchive needs free space for the WAVs again.
- A CLI or stdio MCP job in another process cannot see a take of the app. The take disk check stops the take when the space runs low.
- A FLAC damaged at rest shows its STREAMINFO length, so the media check shows no fault for a truncated FLAC until an unarchive decodes it and names it.
- The Apple encoder leaves allocated blocks after the end of a FLAC file (22.6% of a 68 MB file; a `cat` copy of the file has none). So `du` of `Clips/` after an archive can be 0.60 of the WAV size where the file bytes are 0.54. The report gives the bytes written as file sizes.
- An archive of WAVs that share their data with a copy (APFS clones) frees no space, and the report says so. A backup or a cloud sync that tracks files uploads each changed file again.
- An older build shows "made by a newer version of Dirigible" for an archived package. After the unarchive, the older build opens it again. A FLAC that the unarchive kept as damaged is the one FLAC in a package with no attribute: an older build shows that clip as missing media.
- An unarchived WAV is sample-equal to the WAV before the archive. Its header is the header of the current clip writer, so its bytes can differ from a WAV that an older writer made.
- Each later build keeps the archive version in its reader (0024 P2).

## Alternatives considered

- **A `.flac` path in each `<file>`.** Rejected: each backup, each undo snapshot, and each clipboard record holds the `.wav` path, so a revert or an undo would point at a missing file, and the backups would need a rewrite.
- **No attribute: the files on disk are the state.** Rejected: an older build shows each archived clip as missing media and records new WAVs into the package.
- **Read FLAC in place for every job.** Rejected: the user asked for an unarchive before an edit, and a FLAC seek grows with the position (0003). The gate measured it (see What works). A FLAC with a SEEKTABLE is backlog 1538.
- **A prune that refuses an archived package.** Rejected: the studio prune unarchives first, so the CLI and MCP prune do the same through the one step.
- **A copy of the session in FLAC, as Reaper does.** Rejected: the tester wants the space back in place.
