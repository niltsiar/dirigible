# 0077. Drift fit: a drift-corrected file keeps a link to its source, apart from the render chain

- Status: accepted
- Date: 2026-11-19
- Accepted: 2026-11-19, after the plan gates (2 rounds) of run `2026-11-19-waveform-drift`.
- Amends: 0076 (Sync to track gets a drift option; the sentence "The drift correction of F74 amends this record, 0057 (an origin kind for the drift correction), and 0024" is done by this record), 0003 (a `<file>` can hold one `<drift>` element), 0024 (`session.xml` version 19, `driftSessionVersion`, with a drift link), 0057 (a drift-corrected file is the root of a render chain; D7 holders keep a drift source; D11 copies the words of the source into the drift file once, through the time map), 0047 (a drift source is held), 0011 and 0041 (`dirigible clip sync --drift`, the `clip_sync` argument `drift`), 0040 (the resample uses `ClipConversion`, the one conversion of finalize and import, with a source rate that is not a whole number).

## Context

F74 L2 (Release 6 item 5, R7) aligns an outside recording that has its own clock: the file that a remote guest recorded, a backup recorder, or camera audio. Sync to track (0076) moves the clip by one lag and reports the spread of 3 excerpt lags. The clip still drifts: 50 ppm is 180 ms in one hour. The tester corpus has USB microphones at 47993.5 Hz (-135 ppm, 486 ms in one hour) and 47993.9 to 47997.9 Hz.

Reference apps (`docs/research/waveform-sync.md`):

- PluralEyes: "Correct Audio Drift" is on by default. It writes a new audio file for each corrected original (finding 3).
- Double Ender: it patches or removes silence to offset the drift, with no resample; one fit for each segment (finding 8).
- Final Cut Pro: no source says that Synchronize Clips corrects drift (finding 1). Hindenburg PRO: no waveform sync or drift feature found (finding 5).
- Raffel and Ellis: one global resampling ratio, then local offsets from windowed cross-correlation, then a windowed-sinc resample (finding 18).

Facts of the code on main eac15f749:

- `RenderOrigin` (`Model.swift`) maps file frame i to source frame `offset + i`. Each consumer adds offsets: `Session.root(of:)`, `lower` (Restore Original and the D4 re-render), and `check` and `copiedWords` (all in `Session+Origin.swift`), `TakeMap` (`TakeMap.swift`), the transcript reads (`Session+Transcript.swift`), and `FileWords` (`Session+FileWords.swift`).
- `ClipConversion.convert(_:file:from:to:into:)` (`Finalize/ClipConversion.swift:42`) takes the source rate as a `Double` and relabels each input block at that rate before one `AVAudioConverter` (quality max, algorithm Normal), with the A11 second pass for a peak over full scale and a `span` of input frames.
- `renderRequest` (`Render/ClipRenderPlan.swift:187`) is the one body of a render for `Studio.renderClips` (a blocking run of kind `.clipRender`) and for the closed-package `ClipRenderWork`.

Probes of the run (MacBookPro15,2):

- P1: a 997 Hz tone in a CAF that claims 48002.4 Hz, converted by `afconvert` (the AudioConverter of `AVAudioConverter`) to 48000 Hz at quality 127, complexity Normal: 28801440 frames in, 28800001 out (expected 28800000.00), and the tone phase moves 0.0000 ms over 597 s. The converter honors a source rate that is not a whole number as an exact ratio.
- P2: 60 s of real speech of the corpus, as a 44.1 kHz original. Two resamples (44.1 to 48 kHz at the import, then 48002.4 to 48 kHz for the drift) against one resample (44102.205 to 48 kHz) differ by -144.9 dBFS RMS, 120.3 dB under the signal. The control (no drift correction) differs by 2.8 dB under the signal.
- P3: the rules of **Fit** on worked fixtures, 200 seeds each.

## Decision

**D1. A drift link, not a render level.** A drift-corrected file has `AudioFile.drift: DriftOrigin?`, apart from `AudioFile.origin`. `DriftOrigin` holds the source file (`source`), the source frame of file frame 0 (`offset`), the source frames for each file frame (`ratio`, a `DriftRatio`), and the gain that the edit added to the clip, the A11 gain after the clamp (`addedGain`, as `RenderOrigin.addedGain`; D9). File frame j is source frame `offset + j x ratio`. A file has an origin or a drift link, never both.

- For the render chain (0057), a drift-corrected file is a root. `root(of:)`, `lower`, Restore Original, the D4 re-render, and `TakeMap` stop at it, so their frame sums do not change. Restore Original on a clip with effects on a drift-corrected file goes back to the drift-corrected file, which stays aligned. Undo is the way back to the drifting audio.
- The source of a drift link is a plain file: no origin, no drift link, and no capture. So a drift link never stacks, and a take file (aligned by its anchor, 0004) never gets one, nor a split half of a take (it keeps the capture of the take, `ClipRun.swift:66`). One Session check holds the rules of a drift link (D4), and the not-correctable cause of D10 uses the same predicate, called on the same file: the resample source (D4).
- `DriftRatio` holds a `Double` with |ratio - 1| under 1000 ppm. Its init refuses a value that is not finite or is outside that range.

**D2. Holders.** `filesInUse` (`Session+Origin.swift`), the one owner of the held set, follows one link step at each level of the chain: the origin source or the drift source. So Remove Unused Files keeps the source under a render of a drift-corrected file (clip, rendered file, drift-corrected file, source). `Session.removeFile` refuses a file that a drift link names (`.fileIsSource`). `removeFiles` orders by the depth of that chain, so each file goes before the file that it links to. A paste into another package copies the clip files with no drift link (0057 D8). A clipboard record in the same package keeps it: `keptFiles` of the clipboard (`Studio+Files.swift`) follows the same link step.

**D3. Words.** At the fix, the words of the file that the clip plays, in the span of each new file, are copied into that file through the time map: a root anchor at source frame f goes to file frame round((f - offset) / ratio). For a first fix that file is the source. For a second fix (D5) it is the first drift-corrected file, which holds the words of a Transcribe after the first fix, and the map goes from new file frame to source frame to first file frame. The copy uses the one helper of 0057 D11, with the time map as a parameter. A drift-corrected file is a root, so its words load as the words of a plain file.

**D4. Format.** `<file>` holds one `<drift source offset ratio gain/>` element. `ratio` is the shortest decimal text that reads back to the same `Double` (`String(describing:)`); `gain` is the added gain in dB, as the `gain` of `<origin>`. The writer writes it from version 19 (`driftSessionVersion`, `matchSessionVersion` + 1), and a session with no drift link keeps its lower version (0024 P6). The reader parses the element and refuses `<drift>` in a file of a lower version and two `<drift>` elements in one file. It sets the drift links after all files, as the origins (0057 D9). Each other rule is one Session check, `check(_ drift:of:)` next to `check(_ origin:of:)`, which `addFile`, the load step after all files, and `addDriftFile` call, so the edit cannot save a session that the reader refuses. `Session.driftSourceFault(of:)` is the predicate for a source file: it names the first fault of an origin, a drift link, or a capture. Its argument is always the resample source, `file.drift?.source ?? file`: the check calls it on `link.source`; the D10 gate calls it on the resample source of the clip file, so a second fix (the clip plays a drift-corrected file, which has a drift link) is not refused, and only the capture fault gives the cause `takeFile`; the sheet calls it on the same file and disables the box only for the capture fault. A clip on a file with a render origin keeps the box on and gets the cause `renderedFile` in the result (D10). The check refuses: a file with an origin and a drift link, an unknown source, a source that is the file, a source with an origin, a drift link, or a capture, another layout, a ratio that is not finite or is 1000 ppm or more from 1, an offset under 0, a gain that is not finite or is outside `Gain.range`, and a last frame past the source (`offset + Double(length - 1) x ratio` over `source.length`: the converter writes up to 1 frame past the exact length, P1).

**D5. The resampled file.** Each new file is `Clips/<stem>.wav`, 24-bit at the session rate, written through `NewClipFiles` with the stem rule of 0040 and the stem "<source stem> drift". It holds the source span of its clip piece with the handles of `clipRuns` (the clip range plus max(10 s, half a crossfade) at each edge, cut to the file). `ClipConversion.convert` makes it with the source rate `rate x ratio` and `span` set to that source span: one resample. The source is the pool file that the clip plays. For a 44.1 kHz original, the import already made that pool file, so the audio goes through two resamples (P2: 120 dB under the signal). A second drift fix of a drift-corrected clip resamples from its drift source, so the result is again one resample of the pool file; the clip gain takes off the `addedGain` of the first link (the applied gain, D9) and adds the gain of the new convert. The new link holds the composed ratio, the ratio of the first link times the ratio of the new fit; `driftRequest` computes it right after the fit and refuses with the cause `composedRateOutOfRange` (D10) before the resample when it is 1000 ppm or more from 1, so no file is written.

**D6. Measure.** One read gives the lag of 0076 and the drift points:

- The clip is cut into cells of 60 s (the last cell takes the remainder). In each cell, the window is the 10 s with the largest sum of the 50 ms window levels of the clip (the excerpt choice of 0076, with 10 s windows). A 10 s window smears the lag by 2 ms at 200 ppm. The 0076 Phase 4 table gives a median peak of 0.630 at 1 ms of smear and 0.411 at 2 ms, over the match rule of 0.2.
- Each window searches the 2 kHz reference of the read within 60 s on each side of the 0076 lag (an FFT of 2^19 points at 48 kHz), with the match rule of 0076 (0.2 and 3), then the fine step at the session rate. A run of 3 or more windows with no match, and a run of any length at the clip start or end, gets one search of its loudest window over the whole span, and a match there centers the search of the run. The full-span scores of these searches are built once for the measure. A window that fails the match rule gives no point.
- A point is the clip frame of the window center and its lag.

**D7. Fit.** One rate for the clip (one recorder has one clock) and one offset for each segment (a pause of the recorder starts a segment). The rules, with P3:

1. Under 5 points: no fit.
2. slope0 is the median of the slopes of consecutive points. d = lag - slope0 x c.
3. The local scale s is 1.4826 x the median of |d[i] - median(d[i-1], d[i], d[i+1])|. The split gap S is max(50 ms, 6 s).
4. The sorted d values split into clusters at each gap over S. A cluster of 3 or more points is a segment, and so is a cluster of 2 points whose median d is more than 20 ms from each segment. Other points are outliers.
5. Two segments whose time spans overlap give no fit (the lag jumps between two lines). A later segment under an earlier one gives no fit (cause `lagStepsBack`): a pause only adds lag, and the piece of the later segment would cover the tail of the piece before it.
6. The slope is the median of the pairwise slopes inside each segment (Theil-Sen, pooled). The offset of a segment is the median of lag - slope x c.
7. tau is max(1 ms, 4 x 1.4826 x the median |residual|). A point past tau is an outlier. No fit when outliers are over 30% of the points. An end point that is an outlier gives no fit (cause `endOutlier`) only when it is a pause jump: the last point more than S above the line of its segment, or the first point more than S under it. A pause skips source audio, so the lag after it is larger. Each other end outlier is a lone outlier, as an inner one, and the worst residual of the result counts it, so a step under S at an end shows in the result.
8. Least squares with one shared slope and one offset for each segment, on the inliers.
9. No fit when the rate is 1000 ppm or more from 0, or when the ratio 1 / (1 + rate) of a drift link of the line is 1000 ppm or more from 1, the bound of `DriftRatio` (D1). Each bound refuses rates that the other fits: the rate bound from +1000 to +1001.001 ppm, the ratio bound from -999.001 to -1000 ppm. So the cause `composedRateOutOfRange` comes only from an earlier link.

P3 results: at +50 ppm over 60 min with a lag noise of 0.05 ms, the worst rate error is 0.018 ppm and the worst offset error 0.042 ms (200 seeds). 20% false matches inside the clip keep that. The end probe: an end point 5 ms or 12 ms off, either sign, fits with 1 outlier; with 10% false matches anywhere, 20 of 200 seeds give no fit (37 with no outlier allowed at either end). A 20 s pause, and steps of 51 ms and more, give 2 segments; a step of 49 ms stays in one line with a worst residual of 24 ms. A call delay that wanders (AR(1), sigma 1 to 40 ms) gives 1 no-fit and at most 1 false split in 200.

**D8. Cuts between segments.** Between the last point of a segment and the first point of the next, 200 ms sub-windows at 20 ms steps score the two lines at the session rate (the normalized correlation at each line lag; a win needs a score of 0.5 or more). The cut is the step boundary with the fewest wins on the wrong side (the second line before it, the first line after it), and for a tie the middle of the longest run of adjacent tied boundaries (the first such run when two are as long), so a cut in silence falls inside the silence and never on a boundary with more wrong wins. The cut probe: within 20 ms of a gap in continuous speech; the quietest 50 ms after 5 s sub-windows was up to 2975 ms off. The clip splits there (`Session.split`), and each piece gets its own file and place.

**D9. Edit.** The order is the order of an import (0040): convert each new file to its temporary name and read it back, then the session edit on a copy with the written lengths, then the renames. For each piece k with the shared slope m and its offset b_k (the lag at clip frame c is b_k + m x c), ratio = 1 / (1 + m). The new file starts at source frame `offset_k` (the span start). The file record length is the largest length, up to the written length, whose last frame is not past the source (the bound of D4); the WAV keeps its written length, as a record can be shorter than its file (`PasteClipboard.swift:146`). The length probe over -999 to +999 ppm: the cut drops at most 1 frame. For the first clip frame c0 of the piece and its source frame f0, the clip offset in the new file is round((f0 - offset_k) / ratio), its length is min(round(L / ratio), record length - clip offset) for the piece length L, and its start is round(clip start + c0 + b_k + m x c0). The clip gain is its gain plus the gain that the convert returns, clamped to `Gain.range` as an import does (`AudioImport.swift:111`), and the drift link holds the applied gain, the clip gain after the clamp minus the clip gain before the fix (a clip at +95 dB with a returned +3.01 dB gets +96 dB and the link holds +1 dB), so a second fix that takes it off gives back the level before the first fix. The applied gain is in `Gain.range` whenever the returned gain is, so the check of D4 holds for it. The envelope and the ride points move by the same map. The clips under the new range on the track are cut, as `Session.sync` cuts them, and the result names them. The fix is one session edit and one undo entry.

**D10. No correction.** The sync still moves the clip by the 0076 lag, and the result gives why the drift was not corrected, when: the clip is under 5 min, the clip plays a file with a render origin (cause `renderedFile`; the text says to restore the original audio first; a drift-corrected file has no render origin), the resample source of the clip (`file.drift?.source ?? file`) has a capture (cause `takeFile`, a take file or a split half of a take; the capture fault of `driftSourceFault(of:)` called on that source, before the measure), a transcript of the session did not load (cause `transcriptNotLoaded`, before the measure: `addDriftFile` cannot copy the words to the new file, decision 0055), the fit gives no fit (with its cause), a second fix whose composed ratio (D5) is 1000 ppm or more from 1 (cause `composedRateOutOfRange`, checked after the fit and before the resample, no file is written), or the fit has one segment and its line changes the lag by less than 1 ms across the clip (no file is written). A fit with two or more segments is corrected at any rate: each pause moves the lag by more than the split gap, and the pieces split and move even when the rate gives a ratio of about 1.

**D11. Job.** `driftRequest` in `DirigibleAudio` is the one body of the measure, the fit, the resample, and the edit, as `renderRequest` is for a render. `Studio.correctDrift(_:to:within:agent:progress:)` runs it as a blocking run of the new kind `.drift` (an import transport run: `.busy` for the other entry points, the banner with progress and Cancel, a take start yields) and returns a `DriftSyncReport`: the 0076 read, the cut, and the outcome (the fix, or the cause of D10). `Studio.syncClip` stays the read job of 0076. The closed-package work of `clip_sync` calls `driftRequest` too. A throw before the renames leaves no new file. A cancel after the renames removes the new files with `removeMadeFiles`; a fault in the renames or a failed save keeps them as unused files, as a render does (0040, 0054). `driftRequest` throws `DriftFailure`: `.read(SyncFailure)` for the measure, `.write(ClipRenderError)` for the resample and the renames, `.session(SessionError)` for the edit, and `.cancelled` for each cancel (a `SyncFailure.cancelled` or a `ClipRenderError.cancelled` maps to it). The Studio and `SyncWork` map `.read` through `StudioError(SyncFailure)`, `.write` to `.clipRender`, `.session` to `.session`, and `.cancelled` to `.syncCancelled`, so the sheet, the CLI exit code 130, and the MCP text "the sync was cancelled." stay as for a sync. No new error text is needed.

**D12. Surface.** `dirigible clip sync <package> <clip> --to <track> --drift` and the `clip_sync` argument `drift` (default false, so the 0076 text and JSON stay for a call without it). With a correction, the text adds `corrected a drift of +52.1 ppm (188 ms across the clip) in one resample; the lag stays within 0.4 ms of the line`, and `split the clip at 31:02.150 (the recording paused 20.000 s)` for each cut. Else `the drift was not corrected: <cause>`. The exit code is the code of 0076. The app sheet has a "Correct drift" checkbox, on by default, as the PluralEyes option; the result banner gives the same lines.

## Consequences

- The `session.xml` version rises once, only for a session with a drift link. The previous build refuses that session (0024 P3).
- A drift fix writes a new WAV of the clip span (about 518 MB for 1 h of mono), and the source stays in the pool while a drift link names it.
- After a drift fix, Restore Original does not undo the drift; only Undo does. An effect render on a drift-corrected clip works as on a plain file.
- A clip with a render origin is not corrected until the user restores its original audio.
- A step under 50 ms in the outside recording stays in one line; the result gives the worst residual. A call track whose delay wanders gives a fit through the wander, and the result gives its size.
- The fix places each segment by its own line; a pause in the last 2 minutes with 1 window after it gives no fit, so a tail is never placed by the wrong line. A false match at an end that jumps over 50 ms in the direction of a pause also gives no fit (the end probe: 15 of 200 clips at 10% false matches).

## Alternatives considered

Rubric: (1) the frame sums of the render chain stay exact; (2) the user keeps a way back, and a second fix is still one resample; (3) the format change is small and refusable; (4) the change touches few existing call sites; (5) a later feature (Import Session, F151) reuses the link.

- **A. The drift as a level of the 0057 render chain** (a `RenderOrigin` with a ratio). It meets (2) and (5). It fails (1) and (4): `root(of:)`, `lower`, `check`, `TakeMap`, the transcript reads, `copiedWords`, `FileWords`, and the D4 plan all add offsets, so each needs an affine map, and Restore Original would undo the alignment with the effects. A mistake in one of the 7 sites is silent.
- **B. A drift link apart from the render chain** (chosen). It meets (1): no offset sum crosses a drift link. It meets (2) for a second fix and leaves Restore Original to the effects. It meets (3) with one element and one version. It touches the holders, the format, and one words copy. It meets (5): Import Session can write the same link.
- **C. No link: the corrected file is a plain new file, as an import.** No format change, which meets (3) and (4). It fails (2): a second fix resamples the resampled file, the source can go at the next Remove Unused Files, and the user has no record of what was done. It breaks the non-destructive rule of user decision A8 (0057).
- **One resample from the outside original file** (the release text: "F74 reads the original file"). The import keeps no link to that file (0040). P2 shows that the second resample is 120 dB under the signal, so a file path option gives nothing that a listener hears. Reverse: a `--original <file>` option.
- **One rate and one offset for each segment** (the release text: "one drift fit for each segment"). One recorder has one clock, so a shared rate uses all points; a short segment with 2 points still gets a correct offset. Reverse: a rate for each segment with 5 or more points.
- **A split gap of 5 ms.** P3: with a call delay that wanders by sigma 10 ms, 21 of 200 fixtures give no fit and 22 split falsely; at 50 ms, 1 and 0.
- **Patch or remove silence** (Double Ender). No resample, but it changes the timing of words inside each segment by up to the drift, and a recording with no long silence cannot be fixed.
