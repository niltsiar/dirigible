# Eval set of the workflow docs

This file is the regression set of the workflow docs (`AGENTS.md`, `CODING_STANDARDS.md`, `.claude/skills/`, `.claude/agents/`, `docs/principles.md`, and `scripts/`), and of what the product teaches an agent (the rows of type `agent`). Each scenario is a question from a real incident or from a sampled rule of the rule register. Reflect rule 8 and the eval-engineering lens run the scenarios that `scripts/evals-for.sh --quoted <base>` prints: a new scenario, a holdout, or a scenario whose key points quote the changed words of a hunk of a file of its `Files` column.

## How the eval runs

- A doc set is a copy of the docs at one commit. The old set is `3bc03e0`. The new set is the tip of `chore/workflow-consolidation`. For E11-E18, the old set is main at `5b01f78`, and the new set is the tip of `chore/workflow-speed`. For H14, the old set is main at `b5bdf41`. For E20, the old set is main at `339f1a4`, and the new set is the slice 4 commit of `docs/readable-pr-text`. For E21, the old set is main at `339f1a4`, and the new set is the code gate fix commit of `docs/readable-pr-text`. For H14 and the E6 regrade, the new set is the tip of `chore/verify-copy`. For the E18 cost-count set (key point (c) reads the result token), the old set is main at `a54562f`, and the new set is `7bb9de7` of `fix/cost-count`. Its files are in `.scratchpads/runs/2026-10-02-cost-count-fix/eval/e18/`. For E22 and the nav-docs set, the old set is main at `5617ec5`, and the new set is the code gate fix commit of `docs/nav-docs`. For E32-E36, the old set is main at `26b93bb`, and the new set is `2a0aa7b9` of `docs/agents-md-restructure`. An `Old` or `New` cell with `-` has no grade yet.
- For each set, three fresh agents answer each question in a shuffled order. Run r of each set asks the same questions in the same order, so a batch effect is the same for both sets (`scripts/eval/questions.py`). Each agent starts at `AGENTS.md` and `.claude/skills/deliver/SKILL.md`. It opens another file only through a pointer in a file that it already read, and it quotes that pointer.
- Each step of an answer is a verbatim quote and its path. A quote check drops a quote that is not in its file, and a quote from a file that the agent reached with no pointer.
- A blind grader sees the question, the key points, and the surviving quotes, with neutral labels that mix the old and the new answers. A scenario passes in a run when a quote holds each key point. The grader also marks a key point of which the question asks no clause. A marked key cannot fail the verdict alone: `grade.py verdict` prints `unasked fail`, and the run fixes the question or the key. A scenario with half or more of its key points marked keeps the count of all key points and prints `unasked majority`.
- `retention` means that the old docs can pass the scenario. `policy` means that the old docs fail it by design, because decision 0028 changed the rule.
- The pass rule (run `2026-09-30-workflow-consolidation`, criterion C6): the sum of retention passes of the new set is at most two standard deviations below the sum of the old set (the bound 2 x sqrt(sum of k x p x (1 - p)) of the live retention scenarios, with k the runs of both sets and p the pooled pass rate, that `grade.py verdict` prints); after six runs, no scenario of the new set is two or more passes below the old set; each policy scenario passes in at least two of three runs (four of six). Under six runs, a policy miss of an E scenario that six runs can still pass prints `rerun due` (`rerun-due.txt`) and is not a fail yet. A holdout that both sets fail in each run is void. A fail of holdouts only does not fail the verdict: `grade.py verdict` prints each `holdout fail <H>: no changed text` line and writes it to `holdout-fails.txt` of the eval folder; `check-governance.sh` stops the land when the newest done run that scored the same holdout has it in that file.
- Void list: H1, H13. Both sets fail them in each run (0 passes; H3 passes in 9 runs, so it is not void), so `scripts/evals-for.sh --quoted` does not print them. An ID leaves the list when a run fixes its grader or its docs.
- E1 key point (c) scores as policy, not retention (decision row of the code gate, D12). The E1 scores below leave out (c). The new set passes E1 (c) in 6 of 6 runs, and the old set in 0 of 6.
- Run `2026-10-12-pipeline-reuse` changed E12 key points (b) and (c): the pairs give the bench verdict, with no separate `make bench`. They score as policy: the old set fails them by design.
- Run `2026-10-13-controls-on-demand` changed E1 (a) and (c), E4, and E13 to the mutation pass rule, and the E3 and H4 premises to its words (code gate 1 item 8; E3 stays retention) (no slice-time control, no replay, one pass for `risk: yes`). They score as policy: the old set fails them by design. Its code gate 2 item 1 added E39 (a fix after the pass) and changed the H4 premise to it.
- Stall rule: after two fix cycles in which a scenario stays below its pass rule, the next cycle edits no doc for it. It sorts each failed answer by cause (the rule is not in the docs, the answer does not quote it, the key point is out of reach, or the scenario or the grader is wrong) and reports the result. A fix for a key point out of reach puts its key words in the sentence of the trigger, because an answer quotes one sentence.
- A key point states only what a doc of its Files cell states and what its question asks. A key that a branch adds or changes gets its grade before the gates: `scripts/check-eval-keys.sh` refuses a phase 6 row and a land when no eval folder of the run holds the exact key text and a `scores.tsv` line of its ID. The lead runs `scripts/eval/run.sh` from the worktree of the branch, in the background; a run agent returns to the lead.
- `scripts/eval/run.sh <eval folder> <old> <new> <IDs> <tag> [--holdout-keys <keys.md>]...` runs a whole eval and prints the verdict; its header holds the rest. Its parts are in `scripts/eval/`, each with a header. The answers, `keys.md`, `labels.tsv`, `scores.tsv`, `holdout-fails.txt`, `grade/`, and the logs stay in the eval folder, not in git.
- A row of type `agent` (E38) runs headless Claude Code on the product, not on the docs. `scripts/eval/agent-tasks.sh` runs its tasks, and `scripts/eval/agent-grade.py` grades them; `questions.py` and `grade.py` do not read the row. `scripts/evals-for.sh --quoted` prints it when a file of its Files cell changes. `scripts/check-docs.sh` fails when a file of `Sources/DirigibleMCP` that defines a tools array is not in its Files cell. The tasks export, record, and load the CPU, so run the row after a push check, a land, or a mutant ends.
